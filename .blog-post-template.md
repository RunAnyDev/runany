# runany.dev Blog Post Template

Use this file as a human-facing reference for new blog posts in `apps/web/src/content/blog/`. It is not loaded by Astro at runtime and is not a generator input.

For GitHub Trending tool posts, prefer the Codex skill at `.codex/skills/github-trending-tool-blog/SKILL.md`; the agent should read the repo README/docs and write a repo-specific article instead of filling this template mechanically.

**Filename convention (SORTING — important):**
Filename format: `YYYY-MM-DD-HHMMSS-[slug].mdx`

The filename MUST start with a timestamp for automatic chronological sorting. The `YYYY-MM-DD-HHMMSS-` prefix is stripped when the URL slug is generated, so the time component orders same-day posts without leaking into the URL.

```
2026-10-19-091200-llm-course.mdx        →  URL: /blog/llm-course/
2026-09-27-091300-mobile-mcp.mdx        →  URL: /blog/mobile-mcp/
```

All 1644 published posts follow this form, and `node scripts/canonicalize-blog-filenames.mjs` reports or renames anything that drifts from it. **Do not include spaces, only hyphens.**

## Standard Article Structure

The structure below is a starting point, not a rigid form. The section names are
suggestions; what matters is that each H2 covers a distinct angle, that the prose
does the reasoning, and that the article ends on a concrete fact rather than a
recap. Do not ship standalone `## Practical Evaluation Checklist`, `## Security
Notes`, `## FAQ` or `## Conclusion` sections: fold that content into the section
where it belongs.

```mdx
> **TL;DR:** One specific sentence that explains what the reader will learn or decide.

## What Is [Topic]?

Explain the tool, project, or concept in practical terms. Include who it is for,
what problem it solves, and what it is not. 2-3 paragraphs.

## Why It Matters

Give context, tradeoffs, and when the reader should care. Avoid generic hype.

## How It Works

The mechanism, not the marketing: architecture, data flow, what runs locally vs
on a server, the stack underneath.

## Setup or Workflow

Real documented commands only, copied verbatim from the source.

```bash
# Use real documented commands only
echo "example"
```

## What to Watch For

Limitations, pricing, licensing, the security model, platform gaps, version
numbers. Put concrete numbers here.

![What the reader sees in the illustration](https://cdn.runany.dev/blog/inline/<slug>-ui.webp)

## Source and Accuracy Notes

List every page actually read, with what each one provided. Keep this
reader-facing; do not include internal writing rules.
```

## Depth requirements (posts published on or after 2026-11-16)

These are enforced by `scripts/mdx_lint.py` and `scripts/validate-blog-posts.test.mjs`,
so a thin post fails the build instead of reaching readers.

| Element | Requirement | Validator floor |
|---|---|---|
| Length | 1200-2000 words | 1100 words |
| H2 sections | at least 5, each a distinct angle | 5 |
| Code blocks | at least 2 | 2 |
| Table | at least one table with 2+ data rows | 3 table lines |
| Inline illustration | at least 1 image on `cdn.runany.dev` with alt text | 1 |
| Cited sources | at least 3 distinct source pages referenced in the body | 3 |

## Inline illustrations

At least one illustration inside the body, hosted on `cdn.runany.dev`, with
descriptive alt text. Prefer a real screenshot from the project's README or site;
generate an abstract concept image only when no real image exists.

```bash
curl -sL "https://example.com/screenshot.png" -o /tmp/shot.png
node scripts/prepare-image.mjs illustration /tmp/shot.png /tmp/shot.webp
node scripts/r2-upload.mjs inline/<slug>-ui.webp /tmp/shot.webp
curl -sI "https://cdn.runany.dev/blog/inline/<slug>-ui.webp" | head -1   # expect HTTP/2 200
```

In the body: `![What the reader sees](https://cdn.runany.dev/blog/inline/<slug>-ui.webp)`.
The frontmatter thumbnail is separate and does not count as the illustration.

## Content Rules

- Write in English.
- TL;DR block is required and must start with `> **TL;DR:**`.
- Use H2 for main sections and H3 for sub-steps.
- Every fenced code block must include a language identifier.
- Use relative links for internal links, for example `/blog/other-post/`.
- Do not include internal agent rules, prompt instructions, generator notes, duplicate tracking, or thumbnail pipeline details in public articles.
- Do not invent commands, versions, ports, env vars, pricing, or claims. Every factual sentence must trace back to a source you actually read.
- Avoid bot-style phrasing like `README says`, `README shows`, `according to the README`, and `the extracted sections`.
- Prose over bullets: a section made only of bullets usually wants to be prose.
- No em dashes, no curly quotes, sentence case headings, no emoji in headings.
