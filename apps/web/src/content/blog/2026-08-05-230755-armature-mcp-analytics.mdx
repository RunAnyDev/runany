## What Is Armature?

Armature is a product analytics platform purpose-built for MCP-based AI agents. When users interact with your product through Claude, ChatGPT, Claude Code, or any MCP client, their sessions normally live inside the AI client's UI — invisible to the product team. Armature gives that visibility back.

The platform captures three layers from every session:

- **User intent** — what the user actually asked for
- **Agent thinking** — the model's reasoning and tool-selection decisions
- **Session trace** — every tool call, response, and completion state

It then reconstructs sessions as replayable traces, scores each one for task success, and groups them into use cases ranked by volume and failure rate.

A separate **MCP CLI Evals** tool turns your top real-world workflows into regression suites. You describe the user's goal; Armature drafts the eval case. Real agents run it against your server and a judge scores the result.

### Step 3: Add the MCP Analytics Tool to Your Server

Follow the language-specific docs at [docs.armature.tech/sdks/](https://docs.armature.tech/sdks/). Each SDK wires in with a single initialization call. The analytics client runs alongside your existing MCP tools and captures sessions without changing your server's behavior.

### Step 4: Configure Session Capture

```python
# Python example (from docs.armature.tech/sdks/python.md)
from armature_mcp_analytics import ArmatureAnalytics

analytics = ArmatureAnalytics(api_key=os.environ["ARMATURE_API_KEY"])

# Instrument your MCP server handlers
@app.mcp_tool()
def create_subscription(plan_id: str, customer_id: str):
    # ... your existing logic
    analytics.capture_session(tool_name="create_subscription", params=locals())
    return result
```

### Step 5: Deploy and Watch Sessions Flow In

Deploy your updated server. Sessions appear in the Armature dashboard within minutes. The free tier includes 1,000 sessions and 100 eval runs per month.

## Deeper Analysis

### What Armature Actually Captures

According to the [How It Works docs](https://docs.armature.tech/how-it-works.md), Armature does not passively log all tool calls from a mirror of your server. Instead, you instrument your MCP server using the SDK, which emits structured telemetry on each tool invocation. This means:

- Sessions are **reconstructed** rather than recorded verbatim
- PII and secrets are **redacted by default** by detection models before storage
- You control what gets sent — the SDK only captures what you wrap

### Analytics + Evals Loop

The two products are designed to complement each other. MCP Analytics identifies the top use cases and recurring failure patterns from live traffic. MCP CLI Evals lets you turn those patterns into test suites that run against every code change.

```
Real user sessions → Top use cases & failure patterns → Eval cases → CI regression suite
```

## FAQ

**Q: Does Armature work with non-MCP agents?**
**A:** The product is designed around MCP. Non-MCP agents (direct API integrations, custom protocols) are not natively supported. You would need to adapt the session model manually.

**Q: How is this different from reading my existing tool logs?**
**A:** Raw tool logs show what was called, not what the user meant or what the agent was thinking. Armature reconstructs the full conversation context — user intent, agent reasoning, and call sequence — into a replayable session with a success score. It also groups sessions by use case automatically.

**Q: Can I run evals without MCP Analytics?**
**A:** Yes. MCP CLI Evals works independently. You can write eval cases manually without having live analytics running.

**Q: What models does the eval judge use?**
**A:** Eval runs use real agents (Claude, GPT, etc.) to execute tasks end-to-end against your server. The judge model scores the output against your criteria. Specific model selection is configurable per suite.
