## What Is XPack?

XPack bills itself as the world's first open-source MCP marketplace. The core idea: you have an OpenAPI spec for an API you want to monetize, and XPack wraps it into an MCP service with billing, authentication, and a storefront — deployable in a single command line.

The README puts it plainly:

> **XPack** is the world's first open-source MCP marketplace, to quickly create and sell your own MCP services in just minutes.

**What you get out of the box:**
- One-click OpenAPI to MCP service configuration
- SEO-friendly homepage and service listing pages
- Built-in billing: per-call or token-usage metering
- Stripe Payment integration for actual money collection
- Email and Google OAuth sign-in for end users
- User account management dashboard

Everything is open-source under Apache 2.0 — the billing and storefront code is yours to run on your own infrastructure.

## Setup Workflow

### Option 1: Quick Start (10-minute deploy)

The README's simplest path — one command to bootstrap everything:

```bash
curl -sSO https://xpack.ai/install/quick-start.sh; bash quick-start.sh
```

This handles the full stack: MySQL, Redis, RabbitMQ, and the XPack services themselves.

### Option 2: Docker Compose

**Prerequisites:**
- Docker >= 20.x
- Docker Compose standalone >= 2.x

**Step 1:** Clone the repository:

```bash
git clone https://github.com/xpack-ai/XPack-MCP-Market.git
cd XPack-MCP-Market
```

**Step 2:** Edit `docker-compose.yml` with your environment. The repository provides a reference config at `scripts/docker-compose.yml`:

```yaml
version: '3'
services:
  xpack-mysql:
    image: mysql:8.0.37
    container_name: xpack-mysql
    ports:
      - "33306:3306"
    environment:
      - MYSQL_ROOT_PASSWORD=your_password
      - MYSQL_DATABASE=xpack
  xpack-redis:
    image: redis:7.2.4
    container_name: xpack-redis
    ports:
      - "6379:6379"
  xpack-rabbitmq:
    image: rabbitmq:4.1.2-alpine
    container_name: xpack-rabbitmq
    ports:
      - "5672:5672"
  xpack-mcp-market:
    image: xpackai/xpack-mcp-market
    container_name: xpack-mcp-market
    ports:
      - "8000:80"
    depends_on:
      - xpack-mysql
      - xpack-redis
      - xpack-rabbitmq
```

**Step 3:** Start the stack:

```bash
docker-compose up -d
```

**Step 4:** Access the admin panel at `http://your-server:8000/admin`:
- Username: `admin`
- Password: `123456789`

## Deeper Analysis

### Where XPack Fits in the MCP Ecosystem

The MCP ecosystem has exploded with servers and clients, but the monetization layer has been thin. XPack attacks the problem from the opposite direction: instead of building an MCP client and hunting for servers, you start with an API you want to monetize and get an MCP interface for free.

The use cases XPack targets are clear:
- **API providers** who want an MCP-compatible layer without rewriting their backend
- **Developers** who want to sell access to tools they've built
- **Marketplace operators** who want to aggregate multiple MCP services under one storefront

### What the Stack Looks Like

XPack is a Python FastAPI backend with a Next.js frontend, backed by MySQL (data), Redis (caching/sessions), and RabbitMQ (async job queuing). This is a conventional SaaS stack — production-ready rather than minimalist.

The MCP service generation itself is a templating/transformation step that wraps your existing OpenAPI spec in the MCP JSON-RPC protocol. Whether the generated service is truly "native" MCP versus a REST-to-MCP bridge is an implementation detail worth watching as the project matures.

## Security Notes

XPack handles payment credentials and user authentication — two high-sensitivity areas:

- **Stripe integration** stores no card data locally (Stripe handles PCI scope)
- **OAuth secrets** are stored in the `.env` backend config; ensure these are not committed to version control
- **Default admin password** (`123456789`) is intentionally simple for first-run convenience — change it immediately on any production deployment
- **RabbitMQ** default credentials appear in the sample docker-compose — replace them before any network exposure

## FAQ

**Q: Do I need to modify my existing API to use XPack?**
**A:** No. XPack takes an OpenAPI spec and generates the MCP service wrapper. Your API stays unchanged; XPack translates MCP JSON-RPC calls to your existing REST endpoints.

**Q: Does XPack work with any Stripe plan, or only specific pricing models?**
**A:** XPack supports per-call metering and token-usage billing. For custom subscription or seat-based models, you'd need to extend the Stripe integration.

**Q: Can I white-label the storefront completely?**
**A:** Yes — the frontend is Next.js and fully open-source. You can replace branding, colors, and copy. The docker-compose build argument `--build-arg VERSION` sets the version string displayed.

**Q: Is this production-ready?**
**A:** The project is under active development (Apache 2.0, no commercial support tier). Evaluate the codebase before depending on it for a business-critical billing pipeline.
