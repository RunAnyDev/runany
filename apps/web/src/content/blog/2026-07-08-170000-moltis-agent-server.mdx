## What Is Moltis?

Moltis is a self-hosted personal agent server written in Rust. It positions itself as a secure, auditable alternative to larger agent frameworks — one binary, no Node.js, no npm, no runtime dependencies beyond a container runtime for sandboxing.

The official product description:

> "One binary — sandboxed, secure, yours."

Key differentiators from the official docs and GitHub metadata:

- **Single Rust binary** — the entire server is one compiled binary (~270K Rust lines across 59 crates)
- **Sandboxed execution** — every tool runs inside Docker, Podman, Apple Container, or WASM; no tool runs directly on the host
...provider interface is modular; the official docs document the provider abstraction layer
- **Built-in integrations** — Telegram, Signal, Discord, Teams, Slack, Matrix, Nostr, browser automation, SSH, and MCP servers
- **Voice I/O** — built-in STT and TTS providers (no external voice service required)
- **Memory** — SQLite + FTS + vector memory for cross-session recall
- **Self-improving skills** — can autonomously improve its own skill definitions

The project currently has **2,769 stars** on GitHub and is actively maintained (Rust 1.91+, MIT licensed).

## Installation

The official install page lists four methods:

```bash
# One-liner install script (macOS / Linux)
curl -fsSL https://www.moltis.org/install.sh | sh

# macOS / Linux via Homebrew
brew install moltis-org/tap/moltis

# Docker (multi-arch: amd64/arm64)
docker pull ghcr.io/moltis-org/moltis:latest

# Or build from source
cargo install moltis --git https://github.com/moltis-org/moltis
```

The install script handles binary download and PATH setup on macOS and Linux. The Docker image is multi-arch (amd64 and arm64).

## Configuration and First Run

After installation, the server starts with a web UI for configuration:

```bash
moltis server
```

Key configuration options from the docs:

- **LLM provider** — set your API key and choose from supported providers (OpenAI, Anthropic, local models via Ollama, etc.)
- **Password + Passkey + API keys** — multiple auth methods for access control
- **Vault** — encrypted credential storage
- **Sandbox backend** — Docker (default), Podman, Apple Container, or WASM for tool isolation

The web UI at `http://localhost:PORT` provides a live **Settings → Tools inventory** panel showing all available MCP servers and tool definitions.

## MCP Integration

Moltis supports the Model Context Protocol via two transport modes:

- **stdio** — standard input/output (compatible with most MCP servers)
- **HTTP/SSE** — HTTP server-sent events for remote MCP servers

MCP servers appear in the live Tools inventory in the web UI, making it straightforward to connect third-party tools without additional configuration.

## Security Model

The official docs emphasize security by design:

- Every tool executes inside a sandboxed container — commands never run directly on the host
- API keys and credentials are stored in an encrypted Vault, not in plaintext config
- Host pinning via managed deploy keys in the web UI prevents unauthorized remote access
- Context files are scanned for threats before being used as agent context
- The entire Rust codebase (~270K lines across 59 crates) is auditable; unsafe code is isolated to FFI and precompiled runtime boundaries

## FAQ

**Q: Does Moltis require Docker?**
**A:** Yes — tool execution is sandboxed via Docker, Podman, Apple Container, or WASM. Docker is the default backend. Without a container runtime, tools will not execute in sandboxed mode.

**Q: Can I run it on a Raspberry Pi?**
**A:** The official docs explicitly mention Raspberry Pi as a target platform. The Docker image is multi-arch (amd64/arm64), and the binary install script supports Linux on ARM.

**Q: What LLM providers does it support?**
**A:** The official docs show a modular `moltis-providers` crate (~18.9K lines) implementing the LLM interface. It supports OpenAI, Anthropic, and local models via Ollama. See the provider documentation for the full list.

**Q: How does memory work?**
**A:** Moltis uses SQLite for structured data, Full-Text Search (FTS) for keyword search, and vector embeddings for semantic recall across sessions.

**Q: Is this production-ready?**
**A:** The project has CI, codecov, and CodSpeed benchmarking. It has 2,769 GitHub stars and an active Discord community. As with any self-hosted agent server, evaluate against your threat model before production use.

## Conclusion

Moltis fills a specific niche: a self-contained, auditable Rust agent server that prioritizes security through sandboxing and runs on modest hardware. Its single-binary deployment, modular LLM providers, and built-in voice and memory make it a compelling option for developers who want an agent server without the operational complexity of Node.js or Python stacks.
