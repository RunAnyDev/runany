## What Is Runtime?

Runtime is a platform for deploying **sandboxed coding agents** that have access to your company's actual context — monorepos, microservices, internal tools, APIs — rather than generic open-source codebases. The agents run in isolated environments pre-configured with your team's CLIs, MCP servers, credentials, and custom instructions, then boot in seconds from a snapshot.

The key insight: coding agents like Claude Code and Codex are powerful, but they're typically used by individual developers in ad-hoc ways. Runtime wraps them in an enterprise-grade runtime layer that provides:

- **Environment standardization** — every agent session boots into an identical sandbox with the same tools, versions, and access controls
- **Trigger flexibility** — agents can be invoked from Slack channels, Linear tickets, GitHub issues, CLI, or a browser-based Mission Control dashboard
- **Governance and visibility** — live session monitoring, cost tracking per agent/user/team, spend limits, allowlists, and approval gates
- **Specialization** — teams can build purpose-built agents (alert inspector for `#incidents`, sales prospector for `#revenue`, support triager for inbox) that anyone can tag from their existing workflows

## How It Works

### Environment Setup

You define a sandbox environment once, and Runtime snapshots it for instant boot:

```bash
# Install tools from multiple package managers
mise install
npm install -g @datadog/cli
brew install stripe

# Connect internal services
# (Salesforce, NetSuite, custom APIs via MCP servers)
```

The environment includes:
- Any CLI tools your team uses (`mise`, `npm`, `brew`, `github`)
- Integrations with monitoring (Datadog), CRM (Salesforce), payments (Stripe), ERP (NetSuite)
- Custom MCP servers for internal tools
- Custom instructions and skills specific to your codebase
- Guardrails and secrets management

### Triggering Agents

Agents can be invoked from wherever your team already works:

**From Slack:**
```text
@runtime-agent Fix the login timeout bug in #engineering
```

**From Linear:**
Tag an agent in a ticket comment, and it investigates, ships a PR, and posts findings.

**From CLI:**
```bash
runtime run --agent alert-inspector --channel "#alerts-eng"
```

**From Browser:**
The Mission Control dashboard lets anyone on the team (engineering, support, sales) prompt an agent, watch it work live, and collaborate mid-session.

### Mission Control

The dashboard provides:
- **Live visibility** into every session: tool calls, chain of thought, file changes
- **Cost tracking** per agent, per user, per team
- **Spend limits** and approval gates
- **Session handoff** — collaborate in real time, then ship the result as a PR, deploy, message, ticket, or report

## Security Notes

Runtime emphasizes:
- **Sandboxed execution** — agents run in isolated environments, not on production infrastructure
- **Secrets management** — credentials are injected into sandboxes, not hardcoded
- **Approval gates** — sensitive actions can require human approval
- **Allowlists** — restrict which tools and APIs agents can access
- **Audit trail** — every session is logged with full visibility into tool calls and file changes

## FAQ

**Q: Do I need to install anything locally?**  
**A:** No. Runtime is a cloud platform. You define environments in the dashboard or CLI, and agents run in cloud sandboxes. You can trigger them from Slack, Linear, GitHub, CLI, or browser.

**Q: Can I use my own API keys for Claude Code, Codex, etc.?**  
**A:** Yes. You bring your own keys for the coding agent providers you want to use.

**Q: How is this different from just using Claude Code directly?**  
**A:** Claude Code is a single-developer tool. Runtime adds team-level features: standardized environments, trigger flexibility (Slack/Linear/GitHub), governance (cost tracking, spend limits, approval gates), and the ability for non-engineers to use agents.

**Q: Can agents access our internal tools and APIs?**  
**A:** Yes. You can install any CLI, connect any API via MCP servers, and inject credentials securely. The environment snapshot includes all of this.
