## What Is Ghidra MCP Server?

Ghidra MCP Server is a production-ready [Model Context Protocol](https://modelcontextprotocol.io/) (MCP) server that bridges [NSA Ghidra](https://ghidra-sre.org/)'s binary reverse engineering capabilities with any MCP-compatible AI client — including GitHub Copilot, Claude, and Cursor.

The project was built by a working reverse engineer, not as a demo. It covers the full analysis lifecycle:

- **Decompilation and disassembly** — function analysis, call graphs, cross-references, string extraction
- **Data structure discovery** — struct, union, and enum creation with field analysis
- **P-code emulation** — run any function in isolation via Ghidra's `EmulatorHelper`; brute-force API hash resolution in milliseconds
- **Live debugger integration** — 17 Java endpoints plus 22 Python bridge tools over Ghidra's TraceRmi framework (dbgeng on Windows PE, gdb/lldb otherwise)
- **Automated documentation** — a 7-step Function Documentation Workflow V5 with Hungarian notation, type auditing, and completeness scoring

## Setup Workflow

### Prerequisites

- **Python 3.10+** with pip
- **Java 21 LTS** (OpenJDK recommended)
- **Apache Maven 3.9+**
- **Ghidra 12.1.2** (or compatible version)

> Ghidra 12.1.2 ships Jython as an optional extension. Java scripts work by default, but `.py` scripts in `ghidra_scripts/` require installing the Jython extension from **File > Install Extensions** and restarting Ghidra.

### Step 1: Install the Server

The recommended install command for all platforms:

```bash
python -m tools.setup
```

The `setup` module runs two sub-commands:

- `ensure-prereqs` — installs runtime Python requirements and Ghidra JARs into the local Maven repository
- `deploy` — copies build output, installs the user-profile extension, and patches Ghidra user config

After installation, launch Ghidra and the MCP server connects automatically.

### Step 2: Connect an AI Client

Once the server is running inside Ghidra, any MCP-compatible AI client can connect. The server exposes 251 tools normalized for GitHub Copilot CLI and CAPI validation. Tool names use lowercase letters, digits, underscores, and hyphens only — no nested HTTP paths.

## Deeper Analysis

### Convention Enforcement

A standout feature in v5.0 is **built-in convention enforcement** that moves naming standards into the tool layer:

| Tier | Behavior | Example |
|------|----------|---------|
| **Auto-fix** | Applied silently | `count` field on `uint32` → auto-prefixed `dwCount` on save |
| **Warn** | Change allowed, warning returned | `processData` → "name should be PascalCase with a verb: `ProcessData`" |
| **Reject** | Change blocked | `undefined → undefined` type change → "no-op rejected, type unchanged" |

This means AI agents and human engineers produce consistent output across sessions and models — no need to paste a style guide into every prompt.

### Batch Operations

For large binaries, batch operations reduce API calls by up to 93 percent. Bulk renaming, commenting, typing, and label management run through a single transaction rather than hundreds of individual calls.

### Cross-Binary Documentation Transfer

SHA-256 function hash matching propagates documentation across binary versions automatically. Document a function once, and it applies everywhere the same hash appears — useful when comparing binary versions or analyzing multiple builds of the same software.

## Security Notes

- The MCP server runs as a Ghidra plugin inside the same process as Ghidra itself — a fully trusted environment for reverse engineering
- No network exposure by default; AI clients connect over localhost
- Review Ghidra's own security model if analyzing untrusted binaries
- Batch operations use atomic transactions — partial failures roll back cleanly

## FAQ

**Q: Does this work with headless Ghidra (no GUI)?**
**A:** Yes. The server runs in both GUI and headless modes. Docker and CI/CD pipelines are supported.

**Q: Which AI clients are supported?**
**A:** Any client implementing the Model Context Protocol specification. GitHub Copilot CLI, Claude Desktop, and Cursor have been validated by the community.

**Q: What is the minimum Ghidra version?**
**A:** Ghidra 12.1.2 is the recommended minimum. Older versions may work but are not tested.

**Q: How is this different from other Ghidra MCP implementations?**
**A:** Most implementations offer read-only access to a handful of tools. This project provides write access across 251 tools, including P-code emulation, live debugging, batch operations, and convention enforcement.

**Q: Does it support Ghidra Server for team collaboration?**
**A:** Yes. Full Ghidra Server integration is included: shared repositories, version control, checkout/checkin workflows, and multi-user collaboration.
