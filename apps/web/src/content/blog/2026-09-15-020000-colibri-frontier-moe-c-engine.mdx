> **TL;DR:** Colibri is a pure-C inference engine purpose-built for mixture-of-experts language models. It has no external dependencies, streams expert weights from disk on demand, and runs frontier MoE architectures on commodity CPUs. The whole engine fits in a small binary.

## What It Is

Colibri is a research-grade inference engine for mixture-of-experts language models, written entirely in C. The premise is simple and ambitious: you should be able to run frontier MoE models on the hardware you already own, without a special runtime, a heavyweight ML framework, or a GPU cluster.

The engine has three properties that define it:

- **Pure C, zero dependencies.** The whole binary builds against the C standard library. No Python, no PyTorch, no BLAS, no CUDA. The deployment story is "copy a binary, run it."
- **Expert streaming.** Mixture-of-experts models only activate a subset of experts per token. Colibri streams the relevant expert weights from disk on demand rather than loading the whole model into RAM. A frontier MoE that would not fit in memory can still run, albeit slowly.
- **Designed for MoE.** Most inference engines are dense-model-first and treat MoE as an awkward special case. Colibri is built around the routing and expert-activation pattern from the ground up.

The result is a tool that lets you download an MoE checkpoint, point Colibri at a directory of expert shards, and run inference on a regular laptop or server.

## Why It Matters

Frontier MoE models (DeepSeek-V3-class, Mixtral-class, and larger) are mostly out of reach for individual developers. The full weights don't fit in RAM on a typical workstation, and the runtimes that support them tend to require GPU clusters or specialized hardware. Colibri attacks that constraint from a different angle: a small, simple engine that can run the same models on commodity CPUs by streaming rather than loading.

This matters for several reasons:

- **Accessibility.** Researchers, students, and indie developers can experiment with frontier MoE architectures without booking cloud GPUs.
- **Transparency.** Pure C means you can read the entire engine, audit it, and understand exactly what it does. There's no hidden accelerator library.
- **Long-tail deployability.** Edge devices, low-power servers, and air-gapped environments can host a small Colibri + expert bundle that wouldn't otherwise be able to run an MoE model at all.
- **MoE-native design.** Engines built for dense models pay a constant overhead for every token. Colibri's routing-aware design is a real architectural bet, not just a port.

For researchers studying MoE inference, Colibri is also a useful reference implementation. Reading the routing and expert-loading code is a faster way to understand MoE mechanics than reading dense-model runtimes and guessing.

## Practical Trade-Offs

A few honest constraints:

- **Speed is not the point.** Streaming experts from disk on a CPU is dramatically slower than a GPU inference stack. Tokens per second will be modest. For interactive chat you'll want a faster runtime; for offline experimentation and small-scale serving it's acceptable.
- **Disk pressure.** Expert streaming works best on fast SSDs. Spinning disks will be painful.
- **Ecosystem maturity.** Colibri is a focused research engine. Don't expect the production tooling (batching servers, observability, hot-reload) that comes with vLLM or llama.cpp.
- **Model coverage.** The set of architectures Colibri supports out of the box is limited to the MoE variants it was designed for. Dense models and odd hybrid architectures may not be supported.

These trade-offs are by design: Colibri is a small, auditable, deploy-anywhere MoE engine, not a high-throughput serving stack. It occupies a deliberately different niche from the GPU-first inference frameworks.

## Who Should Care

Colibri is a good fit for:

- **Researchers** studying MoE architectures, expert routing, or low-resource inference.
- **Independent developers** who want to run a frontier MoE model on a laptop or small server.
- **Privacy-conscious users** who need a fully local, fully auditable inference path.
- **Educators** teaching MoE concepts who want a small codebase to walk through with students.
- **Edge and embedded developers** exploring whether MoE inference is feasible in constrained environments.

If you need high-throughput serving for production traffic, vLLM, SGLang, or llama.cpp remain the right answer. If you need a small, audit-friendly engine that proves MoE inference can run anywhere, Colibri is that.

## Summary

Colibri is a focused, well-scoped project: a pure-C inference engine for frontier MoE language models that streams experts from disk and runs on commodity CPUs. It's not going to replace GPU-first inference stacks for production serving, but as a research and accessibility tool it's a meaningful contribution. The pure-C, zero-dependency design is also a refreshing reminder that small, auditable implementations still have a place in the era of mega-frameworks.
