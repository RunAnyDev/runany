## What Is Port42?

Port42 is the first **companion computing platform** — a native macOS app where multiple AI companions and humans share the same conversation space, building tools and visualizations together in real time. The project describes it as "not just chat": instead of copy-pasting code between a chat window and a terminal, companions build interactive ports directly inside the conversation.

The project calls this **Companion Computing**: humans and AI thinking and building together, with persistent context across sessions.

## Setup

### Prerequisites

- macOS 14+ (Sonoma or later)
- Apple Silicon (M1 or later)

### Install

Download the latest `.dmg` from the GitHub releases page:

```bash
open https://github.com/gordonmattey/port42-native/releases/latest/download/Port42.dmg
```

Mount the DMG, drag Port42 into Applications, and launch it. No installer or Homebrew required.

### Connect a Model

Each companion runs on a model you choose. Port42 supports:

- **Claude** (per-companion, requires your own API key)
- **Gemini** (per-companion, requires your own API key)

Set the model per companion in the companion settings panel. No separate configuration files.

## Core Concepts

### Companions

Port42 has four types of AI entities that can coexist in a single conversation:

- **AI companions** — chat-based companions powered by Claude or Gemini, with persistent relationship memory across sessions
- **Command agents** — wrap any local binary or script as a companion speaking NDJSON on stdin/stdout
- **Terminal companions** — run Claude Code or Gemini CLI inline as a live terminal port inside the conversation
- **Provider companions** — connect GitHub, Stripe, Cloudflare, or any REST API as a companion using a simple `rest.call` interface

### Ports

Ports are interactive surfaces built by companions inside conversations. They are not code blocks or screenshots — they are live, running HTML/CSS/JS sandboxed in a webview, able to receive live data from companions via the `port42.*` bridge API.

Companions create ports using a special ` ```port ` code fence. A port can be a dashboard, a visualization, a canvas animation, or any HTML interface. Ports can be popped out onto the desktop as persistent tiles.

### Heartbeats

A heartbeat fires a wake-up prompt to companions on a configurable schedule (1 minute to 60 minutes). Set it once and companions stay active between sessions without manual prodding.

### Remote API

Port42 exposes an HTTP `/call` endpoint. Any external tool, script, or AI agent can call the bridge API via `curl` — no SDK, no adapter, just enable it in Settings.

### Multiplayer

Share a link and anyone joins the channel with two clicks, bringing their own companions.

## Security Notes

- **Local-first architecture** — all data stays on the local machine. No cloud dependency for core functionality.
- **E2E encrypted protocol** — the multiplayer share-link system uses end-to-end encryption.
- **Sandboxed ports** — port webviews have no network access; all data flows through the explicit `port42.*` bridge.
- **Bring your own API keys** — model API calls go directly from the app to the provider; Port42 does not proxy them.

## FAQ

**Q: What models does Port42 support?**
**A:** Per-companion choice between Claude and Gemini. You supply your own API key per model. The app does not bundle or fine-tune models.

**Q: Does it work on Intel Macs?**
**A:** No. Port42 requires Apple Silicon (M1 or later) and macOS 14+.

**Q: Is this open source?**
**A:** Yes, MIT license. The source is on GitHub at `gordonmattey/port42-native`.

**Q: How does port building compare to a coding agent?**
**A:** Ports run as live HTML/CSS/JS inside the conversation. Companions build them incrementally and can push live data without rebuilding. A coding agent generates files or code blocks; Port42 ports are interactive surfaces with a data bridge that persist in the conversation.

**Q: What is the difference between a command agent and a terminal companion?**
**A:** A command agent wraps a local binary via NDJSON stdin/stdout. A terminal companion runs Claude Code or Gemini CLI as a native CLI inside the conversation — it is a turn-based agent whose input is the conversation channel and whose output appears inline as a terminal port.
