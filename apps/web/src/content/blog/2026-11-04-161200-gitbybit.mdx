> **TL;DR:** GitByBit is a free extension that teaches Git by having you run real commands in your editor's terminal instead of a simulated one. It ships 48 lessons, quizzes with instant feedback, and a Gitopedia panel you fill as you go. It works in VS Code and Cursor, and the entire core course costs nothing.

## What GitByBit actually is

GitByBit is a VS Code and Cursor extension that turns your editor into a guided Git course. Each lesson gives you a bite-sized task in a side panel, and you carry it out by typing an actual `git` command into your editor's integrated terminal. Once you run it, the extension inspects the real state of the repository and checks whether you did what the lesson asked for.

The author, Alexander Shvets, also wrote Refactoring.Guru. The extension ships under the ID `GitByBit.gitbybit` and is actively maintained, with version 1.5.4 published on October 27, 2026. Open VSX reports 41,415 downloads and a 5.0 average rating, and the project site advertises a 4.9 rating across 149 reviews from more than 41,000 installs.

Nothing here is a simulation. When a lesson covers `git commit`, you run `git commit` against your own files and watch the real output. If you type the wrong command or skip a step, the extension sees what actually happened to the repository, tells you what went wrong, and suggests a way out. Getting stuck for a minute is part of the method, not a detour around it.

## Why it teaches this way

Most Git material teaches by analogy. The lesson uses a toy repository with pretend filenames, or it is a video you watch while your own project sits untouched in another window. You come away understanding the shape of a command without having operated it.

GitByBit inverts that. The lessons run in a workspace you can open and inspect, and the feedback comes from checking what really happened to the repository rather than from an answer key. That difference matters most when something breaks, because the extension can explain the specific failure you caused instead of replaying a generic explanation of the concept.

Two details make it stick. A Gitopedia panel collects the commands, concepts, and best practices you meet as you progress, so the course doubles as a reference table that keeps filling up. Quizzes are interleaved with the lessons instead of dumped at the end. A sample question from the Git history chapter asks what `git revert` does to the commit history, and the correct answer is that it creates a new commit undoing the changes rather than rewriting anything.

## Getting it running

Install from the VS Code Marketplace, either through the Extensions view or from a terminal:

```bash
code --install-extension GitByBit.gitbybit
```

Cursor pulls its extension marketplace from Open VSX, where GitByBit is published under `GitByBit/gitbybit`. If the listing does not show up in your Cursor build, you can pull the bundle directly and install it from the Extensions view:

```bash
curl -L -o GitByBit.gitbybit.vsix \
  https://open-vsx.org/api/GitByBit/gitbybit/1.5.4/file/GitByBit.gitbybit-1.5.4.vsix
```

You do not need a real project to start. The site also runs a browser version, so you can try a lesson before installing anything locally. Once you are in the extension, a lesson takes 5 to 10 minutes and you work through a series of commands in order.

## What the course covers

| Module | What you work on |
| --- | --- |
| 1. Intro to version control | what version control is, why reach for it, first contact with Git |
| 2. Setting up Git | installation, the terminal, configuring credentials, line endings, default branch name |
| 3. Getting files into the repository | `git init`, staging files, committing, reading the status |
| 4. Resetting unwanted changes | comparing working tree to HEAD, discarding local and staged changes, amending the last commit |
| 5. Tagging and branching | referencing commits, tags, branching strategies, creating and switching branches, merging |
| 6. History | browsing history, diffing commits, reverting older changes, resetting branches |
| 7. Remotes and GitHub | creating a remote, adding it, credentials, pushing and pulling, why rewriting shared history bites |

The full main course is 48 lessons, roughly 4 to 8 hours of work, covering 19 Git commands and 27 concepts and best practices, with 55 quizzes along the way. The modules are sequenced the way you actually need them, so setup comes before the first commit and remotes come last, once branching and history make sense.

## Where it stops and what it costs

The core course is free, including every topic in the table above, and it covers what you need to work on your own projects. There is an optional paid add-on called GitByBit PRO with 20 or more extra lessons on the things that only show up in a team: branching and merging in a shared repository, resolving merge conflicts, rebasing, and sending pull requests. It is a one-time payment with a 30-day money-back guarantee, sold for an individual, as a gift, or for a team.

Two things are worth knowing before you commit an afternoon to it. The extension is not open source, and Open VSX records its license as "SEE LICENSE IN LICENSE", so the course content is proprietary even though taking it costs nothing. And the feedback loop only works if Git is installed locally and you are willing to run commands in a real terminal, which makes it a poor fit for reading through on a machine you do not control.

The Gitopedia you fill as you go is the piece that outlives the course, and it stays open once you finish.
