## Six roles and one assistant

The 23 tools are organised by role, and the roles are the interesting part. CEO, Designer, Eng Manager, Release Manager, Doc Engineer and QA is not a list of coding agents, it is a list of the people involved in shipping software, expressed as capabilities the assistant can be asked for.

That framing is a design choice with consequences. A tool that behaves as a release manager and a tool that behaves as a QA reviewer will want different inputs and enforce different things, and a single opinionated set cannot be right for every team's process. The word opinionated in the description is doing the honest work there.

TypeScript as the primary language is worth noting for a Claude Code project, since it means the tools are installable through the Node ecosystem most developers already have.

## When to use it

Treat gstack as a reference configuration rather than a dependency. The MIT license and the TypeScript implementation make it easy to read, copy the parts that match how your team works, and discard the rest. At 135,174 stars it is the clearest example in today's trending batch of a personal agent setup being turned into a public artifact, and that is worth studying whether or not you adopt it.

Two things to check before installing. First, the role assignments are one person's defaults, so the QA and release behaviours in particular are likely to encode assumptions about process that do not match yours. Second, a bundle of 23 tools is a lot of surface area to adopt blind. The wiki and the source are where to confirm what each tool does before you wire it into a workflow you depend on.
