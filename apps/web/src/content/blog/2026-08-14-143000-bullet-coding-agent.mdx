## What Is Bullet?

Bullet is a desktop coding agent for macOS and Windows that positions itself explicitly on speed. Its core pitch: most agents spend significant time embedding and processing entire repositories, so Bullet limits its context window to targeted file reads and focused searches.

From the product page:

> "Targeted search and file reads find relevant code without embedding the whole repo."

The agent ships as a native desktop app (`.dmg` for Mac, `.exe` installer for Windows) rather than a CLI or VS Code extension. Current version is 1.3.28.

## Setup Workflow

### Step 1: Download

Download the latest release from the GitHub releases page:

**macOS (Apple Silicon):**
```bash
curl -LO https://github.com/trybullet/bullet-releases/releases/download/v1.3.28/Bullet-1.3.28-arm64.dmg
```

**Windows:**
```bash
curl -LO https://github.com/trybullet/bullet-releases/releases/download/v1.3.28/Bullet-1.3.28-Setup-x64.exe
```

### Step 2: Install

Open the downloaded `.dmg` file and drag Bullet into your Applications folder, or run the Windows installer.

### Step 3: Authenticate

On first launch, Bullet will prompt you to connect an API key for your LLM backend. The agent works with standard OpenAI-compatible API endpoints.

## Deeper Analysis

Bullet is interesting as a counterpoint to the "bigger is better" trend in coding agents. While competitors add multi-agent orchestration, full-repo embeddings, and extended context windows, Bullet explicitly cuts this away. The tradeoff is clear: you lose some of the holistic repo awareness that lets larger agents reason about cross-file impacts, but gain response latency that feels noticeably snappier on targeted tasks.

The product page makes a direct performance claim — "a faster coding agent than Codex and Claude Code" — which is an audacious positioning that pits it directly against two of the most widely-used coding agents. Whether that claim holds depends heavily on the task profile: targeted bug fixes and focused refactors likely favor Bullet's approach, while larger architectural changes may benefit from the broader context larger agents maintain.

The desktop-native distribution is also worth noting. Most coding agents ship as CLI tools or editor plugins. A standalone app reduces integration complexity but means you step out of your terminal or editor to interact with it.

- No mention of data retention or conversation logging on the product page. Review the privacy policy if this is a concern for your team.

## FAQ

**Q: Is Bullet open source?**
**A:** No. The bullet-releases repository hosts binary builds only. There is no open-source license visible in the repository as of this writing.

**Q: What API does Bullet use?**
**A:** It accepts standard OpenAI-compatible API endpoints, giving you flexibility to use your own proxy or preferred provider.

**Q: How does Bullet differ from a VS Code extension?**
**A:** Bullet is a standalone desktop application. You interact with it as a separate window rather than inside an editor. This trades deep editor integration for a self-contained workflow.

**Q: Does it work offline?**
**A:** Bullet requires an API endpoint to function — it does not run inference locally. Offline use requires a local inference server accessible via its API.

## Conclusion

Bullet takes a deliberately minimal approach to coding agent design. By skipping full-repo embeddings and broad context windows, it targets the 80% of coding tasks that don't need that overhead. The desktop-native packaging makes it easy to try without committing to an editor plugin ecosystem. If you've found larger agents too slow for focused, targeted work, Bullet is worth a look — especially at v1.3.28 as a mature, stable release.
