> **TL;DR:** Hyprland is an independent, highly customizable dynamic tiling Wayland compositor that does not sacrifice on appearance, according to the repository description. It is written in C++, licensed under BSD-3-Clause, and has 39,403 stars and 2,131 forks. The topics are `compositor`, `cpp26`, `wayland` and `wayland-compositor`, and the project site is hypr.land.

## What it is

A compositor is the program that draws your desktop. On Wayland, it is more than that: it is the display server itself, and applications talk to it directly rather than through an X11 server.

Hyprland is a dynamic tiling compositor. The tiling style means windows are arranged automatically into a grid, and "dynamic" means the layout animates and reflows as windows open and close, rather than snapping to a static grid.

The repository description states the goal directly: "Hyprland is an independent, highly customizable, dynamic tiling Wayland compositor that doesn't sacrifice on its looks." The last clause is doing real work in that sentence. Tiling window managers have a history of looking utilitarian, and this one is explicitly positioning visual polish as a feature rather than an afterthought.

It is also independent, which in this ecosystem means it is not a fork of an existing compositor and not tied to one distribution's release cycle.

## Why C++ and why BSD

The language is C++ and one topic is `cpp26`, meaning the project tracks a recent standard. For a display server, that matters in a specific way: compositor code runs on the critical path of every frame you see, and it sits right next to the graphics driver.

A C++ codebase with a permissive BSD-3-Clause license is an unusual combination for desktop infrastructure. Permissive licensing makes it much easier to redistribute in commercial products, and it means downstream distributions can patch it without a licensing conversation.

The project was created in March 2022, and the popularity it has reached since, roughly 39,400 stars, tracks the broader move from X11 to Wayland.

## The Wayland transition is the real story

X11 has been the Linux display standard for decades and shows its age in remote performance, security isolation and modern graphics features. Wayland replaces it with a compositor-mediated architecture where each client gets its own surface and the compositor controls composition.

The switch is the hard part. XWayland exists so unmodified X11 applications still work under a Wayland compositor, and Hyprland supports it. That means you can move to Hyprland without giving up applications that have not ported yet.

If you have been meaning to try Wayland, a compositor like this is the practical entry point, because it does the compatibility work for you.

## How to try it

```bash
git clone https://github.com/hyprwm/Hyprland.git
cd Hyprland
```

Most people do not build this from source. Distributions package it, and the project site hypr.land carries the configuration documentation.

The configuration is the part you will spend your time in. It is a small Lisp-like format that defines keybindings, window rules, animations and layout behaviour:

```ini
# Bind a key to spawn a terminal
bind = $mod, Return, exec, kitty

# Always open new windows tiled
misc, force_default_window_layout = 1
```

Reading that file is the fastest way to understand what the compositor can do, because almost every feature is exposed as a setting in it.

## When to use it

Hyprland fits if you want keyboard-driven window management, if you care about a desktop that looks like you designed it, and if you are ready to live in the Wayland world with its occasional rough edges.

It is a poor fit if you depend on an X11-only application with no XWayland path, if you need a full desktop environment with all the extras, or if you want something that works out of the box on any distribution without configuration work.
