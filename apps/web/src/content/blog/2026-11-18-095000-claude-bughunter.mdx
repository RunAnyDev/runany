> **TL;DR:** Claude-BugHunter is a bundle of 83 Agent Skills that load into Claude Code, OpenCode, Codex CLI and two other harnesses. Describe what you are testing in plain English and the matching skill loads on its own, carrying detection patterns distilled from 681 disclosed HackerOne reports plus current CVE chains for M365, Okta, SharePoint, vCenter and SSL VPN appliances. The bundle is built for assets you own or have written authorization to assess, and its `SECURITY.md` says so explicitly. Expect to hit Anthropic's runtime cyber safeguards on live offensive work, and enroll in the Cyber Verification Program before your first engagement rather than after.

## What Claude-BugHunter is

The usual way people add security knowledge to a coding agent is one large system prompt. The author of this project, Sachin Sharma, tried that and found two failure modes: a generic prompt gives broad but shallow advice, and a pile of bookmarked public reports means re-reading the same material on every engagement.

The bundle takes the second route and formalizes it. It ships 83 markdown skill files, 15 slash commands, and a pattern library of 681 disclosed-report entries (433 of them individually cited so you can audit where a technique came from). Skills are plain [Agent Skills](https://docs.claude.com/en/docs/claude-code/skills) in the `SKILL.md` format, so they are not tied to Claude Code alone.

The [repository](https://github.com/elementalsouls/Claude-BugHunter) describes four stacked layers:

- Think: `bb-methodology` and `redteam-mindset` carry the workflow and the operator discipline
- Hunt webapps: 58 `hunt-*` skills, one per vulnerability class, each with detection patterns, payloads and bypass tables
- Hit the perimeter: enterprise platform chains for M365 and Entra ID, Okta, SharePoint on-premises, VMware vCenter, SSL VPN appliances, Android APKs and supply chain recon
- Ship it: `triage-validation`, reporting and `evidence-hygiene` for severity, out-of-scope rebuttals and redaction

## What the skills cover

The catalog on the [project site](https://elementalsouls.github.io/Claude-BugHunter/skills.html) is browsable and each entry carries a description plus a count of documented patterns.

| Layer | Skills | Representative skills |
|---|---|---|
| Hunt, web app vulnerability classes | 58 | `hunt-xss`, `hunt-sqli`, `hunt-idor`, `hunt-ssrf`, `hunt-jwt-crypto`, `hunt-http-smuggling`, `hunt-cors`, `hunt-grpc` |
| Enterprise platform attack | 10 | `m365-entra-attack`, `okta-attack`, `hunt-sharepoint`, `vmware-vcenter-attack`, `enterprise-vpn-attack`, `apk-redteam-pipeline` |
| Reporting and validation | 6 | `triage-validation`, `evidence-hygiene`, `report-writing`, `bugcrowd-reporting` |
| Recon and OSINT | 5 | `web2-recon`, `offensive-osint`, `osint-methodology`, `recon-scope-triage` |
| Methodology and mindset | 4 | `bb-methodology`, `bug-bounty`, `redteam-mindset`, `bb-local-toolkit` |

Some entries are specific enough to be worth naming. `hunt-jwt-crypto` covers `alg:none` signature stripping and the RS256 to HS256 key confusion that lets an attacker forge a token for any identity. `hunt-cors` breaks origin reflection with credentials, null-origin trust and unanchored subdomain regexes into separate bypass patterns. `hunt-forgot-password` lists five distinct account recovery flaws, from username enumeration through response-body token exposure.

The workflow itself runs in six non-linear phases: scope, recon, map and rank, hunt, validate, report.

## Installing it

There are two supported paths, and the README is blunt about the tradeoff.

```text
/plugin marketplace add elementalsouls/Claude-BugHunter
/plugin install claude-bughunter@elementalsouls
```

The plugin route is the fast one: all 83 skills and 15 commands load namespaced under `claude-bughunter:` and update when the version bumps, with no files copied into your home directory. The clone route gives you more, because the `hunt` engagement scaffolder only ships with the clone.

```bash
git clone https://github.com/elementalsouls/Claude-BugHunter.git
cd Claude-BugHunter
bash scripts/install.sh
```

| Path | 83 skills and 15 commands | `cbh` CLI | `hunt` scaffolder |
|---|---|---|---|
| Plugin | namespaced under `claude-bughunter:` | separate `pipx install` | not included |
| Copy install | copied into `~/.claude/` | included in the clone | included in the clone |

The terminal-native runner installs on its own, so plugin users can add it without cloning the whole repo.

```bash
pipx install git+https://github.com/elementalsouls/Claude-BugHunter
```

## It is not only a Claude Code bundle

The skills use the portable `SKILL.md` format, so the same knowledge layer installs into five harnesses with one flag.

```bash
# macOS / Linux
bash scripts/install.sh --all --burp-mcp

# Windows (PowerShell)
pwsh ./scripts/install.ps1 -All -BurpMcp
```

| Harness | Target skill directory | Flag |
|---|---|---|
| Claude Code | `~/.claude/skills/` | default |
| OpenCode | reads `~/.claude/skills/` and `~/.agents/skills/` | default or `--agents` |
| OpenAI Codex CLI | `~/.agents/skills/` | `--agents` |
| Hermes Agent | `~/.hermes/skills/` | `--hermes` |
| Google AntiGravity | `~/.gemini/config/skills/` | `--antigravity` |

The knowledge layer ports everywhere. The slash commands and the `/hunt` engine stay Claude Code only by design, which is the tradeoff to keep in mind if you run OpenCode or Codex as your primary agent.

The `hunt` command creates a structured engagement folder, which the [usage guide](https://github.com/elementalsouls/Claude-BugHunter/blob/main/USAGE.md) describes with its own output.

```text
Usage: hunt <target-name>
Creates a new engagement folder at $HUNT_BASE/<target-name>
Default $HUNT_BASE is /Users/you/Targets
```

Once a folder exists, Claude Code reads the `CLAUDE.md` engagement context it wrote there, and the phase workflow starts from scope.

## Scope, and what it deliberately leaves out

This is the part that decides whether the project is usable for you. The bundle covers the external attack surface, meaning anything reachable from the internet without first compromising an internal endpoint.

Out of scope by design, and the README presents these as decisions rather than gaps:

- Internal Active Directory attacks including Kerberoasting, DCSync, Pass-the-Hash, AD CS abuse and ntlmrelayx
- C2 frameworks such as Cobalt Strike, Sliver and Mythic
- Post-exploit, persistence and lateral movement, which the author says belongs to a different bundle
- Evasion work such as AMSI bypass, ETW patching and AV or EDR bypass
- iOS pentesting, hardware, RF and ICS
- Binary exploitation, kernel pwn and browser internals

If your engagement includes an internal red team phase with Kerberos domain takeover or lateral movement, this bundle does not cover it, and the authors say so up front rather than letting you find out mid-engagement.

The authorization posture is written down in `SECURITY.md`. The skills are meant for assets you own, in-scope bounty programs, signed engagement letters, CTFs and deliberately vulnerable practice sites. The bundle excludes weaponizing zero-days against unauthorized targets, post-exploitation tooling, malware development and mass-targeting infrastructure. The `triage-validation` gate asks whether a target is in scope and whether the finding is on the program's accepted-impact list before anything gets submitted.

## The runtime safeguard nobody warns you about

There is a practical problem with running this bundle, and the README calls it out directly. Anthropic's models apply real-time safeguards that block vulnerability exploitation and offensive security tooling development by default. Even legitimate, in-scope work can trip a refusal, and that refusal has nothing to do with the bundle.

The supported route for authorized offensive work is Anthropic's free, application-based [Cyber Verification Program](https://claude.com/form/cyber-use-case), which adjusts safeguards for legitimate dual-use cases. Mass data exfiltration and ransomware development stay prohibited and are not adjustable.

A second issue is quieter. On Opus 5, Anthropic names exploit generation, binary-based vulnerability scanning and penetration testing as requests that fall back to Opus 4.8 rather than being refused. You get a notice and the response is labelled, but in a long agentic run it is easy to scroll past, and it looks like the model quietly got worse. The fix is in Settings under Capabilities, where automatic model switching can be disabled.

## Who wrote it, and under what license

Sachin Sharma built this through authorized bug-bounty engagements and authorized external red-team engagements, and the README lists the capability gaps that came out of them: no hypothesis discipline, VRT defaults downgrading P3-worthy findings to P4, findings scattered across folders, screenshots leaking cookies and victim PII, and no enterprise platform chain knowledge.

The project is dual licensed. Code, meaning the Python helpers and shell scripts, is MIT. Content, meaning the markdown documentation, wordlists, regex catalogs and severity rubrics, is CC BY 4.0. Reuse the content commercially if you credit Sachin Sharma and Claude-BugHunter and link back.

Eight of the 83 skills and all 15 slash commands are vendored from `shuvonsec/claude-bug-bounty`, which supplied the methodology, validation, reporting and payload library. A separate tool, `shuvonsec/public-skills-builder`, scaffolds per-class skills from disclosed reports and is not vendored. The documented tool inventory is Burp Suite with its MCP server extension, the ProjectDiscovery suite, SecLists and Assetnote wordlists.

The roadmap is honest about what is missing. HackerOne MCP integration is open, with only Burp MCP wired in today. A per-engagement memory layer for pattern recall across targets is open. `hunt-fintech-graphql` shipped, `hunt-healthcare-fhir` and `hunt-gov-compliance` did not. `docs/cve-coverage.md` tracks CISA KEV coverage and is refreshed weekly by a workflow template.
