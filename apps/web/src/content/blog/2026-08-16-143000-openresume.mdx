## What Is OpenResume?

OpenResume is an open-source resume builder and parser published as a weekend project. Its core promise: a modern professional resume design with zero privacy tradeoffs. Everything runs in the browser — no account, no backend, no data sent anywhere.

The builder has two components:

1. **Resume Builder** — fill in your info and get a downloadable PDF in real time
2. **Resume Parser** — upload an existing PDF to test its ATS readability against platforms like Greenhouse and Lever

It was built by a single developer as a weekend project and later picked up by the HN community (656 points on launch).

## Features

OpenResume's README lists these five core features:

| Feature | Description |
|---|---|
| **Real Time UI Update** | The resume PDF updates instantly as you type — see the final output immediately |
| **Modern Professional Design** | Automatically formats fonts, sizes, margins, and bullet points; ATS friendly to Greenhouse and Lever |
| **Privacy Focus** | No sign-up required. Data stays entirely in your browser — works even offline |
| **Import From Existing PDF** | Upload an existing resume to restyle it to modern design in seconds |
| **Successful Track Record** | Users have landed interviews at Dropbox, Google, and Meta |

The **Resume Parser** uses PDF.js to read the content of a PDF and analyzes it for ATS readability. The algorithm is documented on the site with interactive tables.

## Tech Stack

OpenResume is built with:

- **TypeScript** — static type checking
- **React** — component-based UI
- **Redux Toolkit** — state management
- **Tailwind CSS** — styling
- **Next.js 13** — web framework with static site generation
- **PDF.js** — reading PDF content (parser)
- **React-pdf** — generating PDF output (builder)

## Local Development

The README provides two setup methods:

### Method 1: npm

```bash
git clone https://github.com/xitanggg/open-resume.git
cd open-resume
npm install
npm run dev
# Open http://localhost:3000
```

### Method 2: Docker

```bash
git clone https://github.com/xitanggg/open-resume.git
cd open-resume
docker build -t open-resume .
docker run -p 3000:3000 open-resume
# Open http://localhost:3000
```

## How the Resume Builder Works

The builder page (`/resume-builder`) uses two main components:

- `ResumeForm` — collects user input (name, experience, education, skills)
- `Resume` — renders the PDF preview via React-pdf

As you fill in the form, Redux Toolkit updates the central store, and the `Resume` component re-renders the PDF in real time.

The parser page (`/resume-parser`) uses `parseResumeFromPdf` from `/lib/parse-resume-from-pdf`. PDF.js extracts text from the uploaded file, then the parser applies ATS readability logic.

## ATS Compatibility

The builder targets top ATS platforms — specifically Greenhouse and Lever. It automatically handles:

- Font standardization (typeface, size, leading)
- Margin consistency
- Bullet point formatting
- Section ordering

This means the output PDF should pass basic parsing checks on platforms that screen resumes before a human sees them.

## FAQ

**Q: Is my resume data sent anywhere?**
**A:** No. OpenResume is purely client-side. Your data lives in your browser's memory and local storage only.

**Q: Does it work offline?**
**A:** Yes — once the page loads, the app functions without an internet connection.

**Q: What ATS systems does it support?**
**A:** The README explicitly mentions Greenhouse and Lever. It produces standard-formatted PDFs that should work with any rule-based ATS.

**Q: Can I use it to parse resumes I'm screening as a hiring manager?**
**A:** The parser is designed for candidates to test their own resumes, but there's nothing preventing a hiring manager from using it to check incoming applications.

**Q: Is the source code clean to read?**
**A:** The project structure follows standard Next.js 13 conventions. Key logic lives in `/src/app` with clear separation between pages and components.
