> **TL;DR:** P-JiT 21K is a 2.18B-parameter pixel-space diffusion model that Linum trained for $21,038 of H100 time and released under Apache 2.0. It throws away the VAE entirely, patches images at 32x32 instead of the usual 16x16, and ships with weights, inference code and a prompt upsampler. You can generate a 1024x1024 image on a single CUDA GPU, but it cannot write text and it struggles with crowds, full-body shots and object counts.

## What P-JiT 21K actually is

Linum is a two-person research lab run by brothers Sahil and Manu Chopra, training generative video models from scratch. P-JiT 21K is the image stage of that plan: a text-to-image model released on 4 November 2026 as a research checkpoint, with a long technical write-up on their Field Notes blog, Apache 2.0 weights on Hugging Face, and inference code on GitHub.

The interesting design choice is that it is a pixel-space model. Nearly every diffusion image model compresses pixels into a separate latent space first, using a variational autoencoder. P-JiT removes that component and operates on pixels directly, letting the diffusion model learn its own latent representation as part of the generative process. The argument is that VAEs have an empirical ceiling on compression, and that a VAE tuned for reconstruction can hurt downstream generation.

Compression still happens, just inside the model. Images are split into 32x32 patches, each patch is a flat 3,072-value RGB vector projected down to 1,024 dimensions, and those tokens feed a 22-block diffusion transformer. Text arrives from a frozen Qwen3.5-4B encoder, read at layers 7, 15 and 27. Two image refiner blocks and two text refiner blocks run before the two modalities merge into the trunk.

| Part | Choice |
|---|---|
| Trunk | 22 single-stream DiT blocks, width 2,944, 23 heads x 128, SwiGLU 7,936 |
| Refiners | 2 image blocks plus 2 text blocks, timestep-modulated |
| Patching | 32x32 pixels projected 3,072 to 1,024 to 2,944, giving 1,024 tokens at 1024x1024 |
| Text | Qwen3.5-4B frozen, layers 7, 15 and 27 concatenated, 256 tokens |
| Timestep conditioning | Low-rank AdaLN, rank 256, scale-in and tanh gate-out, following Z-Image |
| Parameters | 2.18B at sampling, 2.42B in training with the readout heads |

Compared with Linum's own v2 model and with FLUX-2 style baselines, which use 16x16 token reduction, the 32x32 patching cuts the attention context window by 4x. That matters because attention is quadratic in sequence length, so a shorter context is the single biggest lever on both training and inference cost.

## Where the $21K went

The training bill is the headline number. The whole release cost $21,038, split across pretraining and a short post-training pass, priced at $2.50 per H100-hour on 64 H100s across 8 nodes.

| Phase | Volume | H100-hours | Cost |
|---|---|---|---|
| Pretraining, 512px stage | 610.27M samples (297,985 steps) | 8,139 | $20,348 |
| Pretraining, 1024px stage | 49.97M samples (24,400 steps) | included above | included above |
| Post-training with FDFO | preference optimisation pass | 276 | $690 |
| Total | 660M samples seen | 8,415 | $21,038 |

Cheap hardware is only half the story. The training recipe is where the money was saved:

- **Noise schedule curriculum.** The first 80M samples use a narrow LogitNormal(0.8, 0.8) distribution so the model learns structure first, then the schedule widens to LogitNormal(-0.2, 1.0) for detail. That switch shifts 107x more training timesteps into the useful band.
- **Muon on the big matrices.** Muon with momentum 0.95 and Nesterov handles the 2D block weight matrices, AdamW covers everything else, and the two are RMS-matched so they play well together.
- **Readouts for gradient signal.** A PixelREPA head at block 5 aligns the latent space with DINOv3-L, and two extra heads after blocks 10 and 16 predict the clean image at quarter and half resolution. Every block in a pixel-space model is already predicting something close to the final image, so these readouts strengthen the early gradient path. They are training-only and are not shipped in the weights.
- **Spike-aware EMA.** Weight averaging pauses for 250 steps when the gradient norm exceeds 10x its rolling median, protecting the EMA copy from instability.

The 1024px stage starts from the 512px EMA weights with a fresh optimizer, doubles the noise scale from 2 to 4 to account for the extra redundancy, and uses RoPE interpolation to keep the position grid aligned across the resolution change.

## Getting it running

The repository expects a CUDA GPU. The DiT weights are 8.7 GB in fp32 and the Qwen3.5-4B text encoder is another 8 GB in bf16, and both download from the Hugging Face Hub on first use.

```bash
sudo apt-get install -y build-essential python3-dev python3-venv
git clone https://github.com/Linum-AI/pjit-21k && cd pjit-21k
python3 -m venv .venv && source .venv/bin/activate
pip install -e .
```

The build tools are not optional decoration. Triton compiles small CUDA shims the first time the package is used.

The model was trained on dense captions of 50 to 80 words, and short prompts produce noticeably worse images. The bundled `generate.py` handles that by rewriting your prompt into a caption of the right shape using Claude Opus 5.5 through OpenRouter:

```bash
export OPENROUTER_API_KEY=...
python generate.py --prompt "oil painting of weathered fisherman smoking a pipe" \
    --aspect_ratio square --seeds 0 --out_dir outputs
```

If you already know how to write a dense caption, skip the API key entirely and pass `--no_upsample`:

```bash
PROMPT="Close-up portrait of an elderly Middle Eastern woman looking calmly into the lens, her face filling the tall frame. A cream headscarf and the collar of a dark green cardigan frame her chin. Soft overcast daylight smooths the fine lines of her skin, and the olive grove behind melts into silvery blur."
python generate.py --no_upsample --aspect_ratio tall --seeds 2 --prompt "$PROMPT" --out_dir outputs
```

The caption the model actually saw gets printed and saved next to the PNGs in `outputs/prompt.json`, so you can diff what you asked for against what was fed in.

`--aspect_ratio` picks one of the five roughly one-megapixel sizes the model actually saw during training:

| Flag | Width x height |
|---|---|
| `square` (default) | 1024 x 1024 |
| `tall` | 864 x 1216 |
| `4:3` | 1152 x 864 |
| `3:2` | 1248 x 832 |
| `16:9` | 1280 x 720 |

Sampling defaults to 50 Euler steps with adaptive projected guidance at scale 15 against an empty negative prompt, with initial noise at scale 4. The initial noise draw is replicated so that a seed produces the same image on any NVIDIA GPU rather than one that varies by GPU model. Pass `--native_noise` if you would rather use the local GPU's own random draw.

## Where it holds up and where it breaks

The model card is unusually blunt about the limits, and you should read it before planning anything around this checkpoint.

- **No text, no posters.** The training data was filtered to remove rendered text entirely (no infographics, PDF pages, slides or book pages), because that data is not useful for animation tools. Prompts asking for words, logos, signs or title cards will not work, and the upsampler rejects them with a `text_requested` error instead of quietly producing garbage.
- **Small model, small model problems.** A 2B DiT struggles with full-body shots, many entities (six cars, crowds of people), interactions between several people, and world knowledge (six strings on a guitar, the dots on a die).
- **Rough edges by design.** Linum labels this a research checkpoint rather than a production model, and describes it as a stepping stone toward their next video model.

The post-training side deserves a note too. The $690 preference pass used a variant of Finite Difference Flow Optimization with JEV-Image and human judges, and the authors are candid that post-training for diffusion is a young discipline. Unlike LLM post-training, diffusion models have no strong likelihood estimates to lean on, so the RL-style recipes that work on language models do not transfer cleanly. Expect this area to move fast.

One more thing worth knowing before you dig into the repo: the inference code, the model card and the Hugging Face README were written by Claude Opus 5.5, pulled out of Linum's internal experiment repository and cleaned up. The model, the training run and the review of the code are theirs.
