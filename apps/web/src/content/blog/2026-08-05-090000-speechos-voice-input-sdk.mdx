> **TL;DR:** SpeechOS is an embeddable voice SDK that adds dictation, AI-powered text editing, voice commands, and read-aloud to any web text field. Integrate via auto-detecting widget or programmatic API — no specialized hardware needed.

## What it is

SpeechOS is built for one specific pain point: sparse, low-quality text entry in CRM and CMS platforms. When text entry is friction-heavy, users leave fields blank, write abbreviated notes, and defer updates. That degrades data quality downstream — sales teams can't filter on incomplete notes, support tickets lose context.

Rather than building voice input from scratch, developers embed a JavaScript SDK that adds four voice capabilities to every text field:

1. **Dictate** — real-time speech-to-text with automatic punctuation and filler-word removal
2. **AI Edit** — shorten, rewrite, translate, or summarize dictated text using voice commands
3. **Voice Commands** — trigger workflows like "log activity" or "submit form" without touching the keyboard
4. **Read Aloud** — have any selected text spoken back for proofreading

Performance claims from the product page, citing a Stanford HCI text-entry study: roughly 3× faster than typing, latency under 500 ms, dictation throughput of 160+ words per minute, and a 20.4% lower error rate than OS-native dictation.

## Two integration paths

The fastest path is genuinely zero-code. Drop one script tag and the widget appears automatically when users focus any text input, textarea, or contenteditable:

```html
<script src="https://cdn.speechos.ai/widget.js"></script>
```

That auto-detects every editable element on the page. No per-field configuration. For custom UI or headless integrations, call the API directly:

```javascript
import { useDictation, useEdit, useTTS } from '@speechos/sdk';

// Start dictation
const { dictate, stop } = useDictation();
dictate();

// AI edit a phrase
const { edit } = useEdit();
edit('shorten this');

// Read text aloud
const { speak } = useTTS();
speak(selectedText);
```

React hooks are available for the same three primitives: `useDictation`, `useEdit`, `useTTS`.

A Chrome extension is also shipped that enables voice dictation on any website without installing the SDK — useful for a quick trial before committing to integration work. A live demo runs directly from the product page.

## Why SDK-level instead of OS-level

OS-native dictation (macOS Voice Control, Windows Voice Input) produces raw transcripts that still need manual cleanup. The SDK-level approach lets SpeechOS apply punctuation rules, filler-word removal, and structured output formats at the transcription layer rather than as post-processing. That's the difference between "the user said 47 uh um like" and a clean CRM-ready sentence.

The Voice Commands module is what separates SpeechOS from built-in browser speech recognition. Product teams can map voice phrases to application actions — "Log activity" triggers a CRM activity log entry, "Submit form" submits the current form, "Read this back" plays TTS of selected text. This is a different product tier than pure dictation.

## Practical considerations

If you're considering SpeechOS for a production CRM deployment, a few things to verify upfront:

- **Pricing** is not published on the public marketing page — contact the SpeechOS team for enterprise or high-volume pricing
- **Data handling** — voice data is processed through SpeechOS infrastructure, so review their data retention and encryption policies before processing customer PII through CRM voice fields
- **Latency** — the SDK calls a remote API, so test latency in your target deployment region
- **Sensitive fields** — the product page does not document field-level exclusions for passwords or payment information; consult SpeechOS documentation before enabling voice input on sensitive forms
- **Self-hosting** — none documented on the product page; SpeechOS is SaaS-only

For a quick win, try the live demo on a long-form text field and compare the dictation quality against OS-native dictation for your accent and domain vocabulary. The AI Edit commands (shorten, translate) on messy dictation input are where the product earns its keep — if those work well for your use case, the rest of the integration is straightforward.
