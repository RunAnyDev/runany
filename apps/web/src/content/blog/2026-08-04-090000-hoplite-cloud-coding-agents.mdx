## TL;DR

> **TL;DR:** Hoplite (YC S26) deploys cloud coding agents that work in isolated development environments, verify their own changes, and open GitHub pull requests — so you hand off implementation and review the code.

## What Is Hoplite?

Hoplite is a cloud-based coding agent platform from Y Combinator's Winter 2026 batch. It takes a software task and drives it to completion: reading and editing code, running tests, verifying changes in a sandboxed environment, and opening a GitHub pull request when ready.

Unlike a local AI coding assistant that runs on your machine, Hoplite agents work in **isolated cloud environments**. This means:
- No污染 your local dev setup
- Agents can run in parallel across multiple threads
- Repository access is scoped through a GitHub App installation
- Sensitive actions (like pushing to main) require your approval

## Setup Workflow

### Step 1: Connect a GitHub Repository

1. Sign up at [app.hoplite.sh](https://app.hoplite.sh/) and create a workspace.
2. Install the Hoplite GitHub App on the repositories you want to give agents access to.
3. Configure the base branch, a setup script, and any encrypted environment variables the project needs.

```bash
# Example: After installing the GitHub App and adding a repo,
# configure it via the Hoplite dashboard at app.hoplite.sh
```

### Step 2: Start a Thread with a Task

A **thread** is a persistent agent session. You give it a task, and it works on it across multiple steps.

```
Task example: "Add a rate limiter to the /api/users endpoint
that throttles to 100 req/min per IP address."
```

### Step 3: Monitor and Approve Sensitive Actions

Hoplite shows you what the agent is doing in real time. For sensitive operations (e.g., pushing to the main branch, accessing secrets), you approve or reject before it proceeds.

### Step 4: Review the Pull Request

The agent opens a PR with:
- A description of what changed
- Verification evidence (test results, lint output)
- Any notes on tradeoffs or alternative approaches considered

You review, request changes in-thread, or merge.

## Key Features

### Isolated Cloud Environments

Each thread runs in its own sandboxed environment. Agents can install dependencies, run builds, and execute tests without affecting your local machine or each other.

### MCP Server Integration

Hoplite exposes an MCP (Model Context Protocol) server at `https://api.hoplite.sh/mcp`. You can drive Hoplite agents from any MCP-compatible client, with OAuth protection on all streams.

```bash
# MCP server endpoint
https://api.hoplite.sh/mcp
```

### CLI Import

Import local Claude Code, Codex, or OpenCode agent history and manage project skills from the CLI:

```bash
# Requires the Hoplite CLI — see hoplite.sh/docs/cli
```

### Verification Evidence

Before opening a PR, the agent runs your test suite and presents the results. You see exactly what passed and what failed, with logs, before you review the code.

### GitHub App Authorization

Repository access is not via personal access tokens. Hoplite uses a GitHub App installation, which means:
- You can scope access to specific repositories
- Permissions are explicit and revocable
- No token expiry or rotation needed

## Pricing

## FAQ

**Q: Is there a self-hosted version?**
**A:** No. Hoplite is a cloud service. There is no self-hosted or open-source option documented.

**Q: Which LLMs does Hoplite use?**
**A:** Hoplite abstracts the LLM layer. The agent-facing capability list is at `hoplite.sh/agents.txt`. You can configure which model to use per workspace via the dashboard.

**Q: Can I use Hoplite with GitLab or Bitbucket?**
**A:** No. Hoplite currently only supports GitHub via the GitHub App integration.

**Q: What happens if the agent introduces a breaking change?**
**A:** The agent runs your test suite in the sandbox before opening a PR. You review the verification evidence (test results, build logs) before merging. Sensitive operations like force-pushing or modifying protected branches require explicit approval.

**Q: Does Hoplite store my code?**
**A:** Code is processed in isolated cloud environments scoped to your workspace. Hoplite's [privacy policy](https://hoplite.sh/privacy) governs data handling. Encrypted environment variables are stored securely and never exposed to agents unless explicitly authorized.

## Conclusion

Hoplite automates the full implementation cycle — from task description to verified, PR-ready code. Its cloud isolation, GitHub App authorization, and real-time approval gating make it a solid choice for teams that want AI coding agents without the operational overhead of running them locally.

If you want agents that **just handle the implementation** and hand you a PR to review, Hoplite is worth trying at [hoplite.sh](https://hoplite.sh).
