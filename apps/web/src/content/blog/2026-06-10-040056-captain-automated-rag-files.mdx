## TL;DR

> **TL;DR:** Captain is a self-hosted RAG engine that automatically processes your files into a searchable knowledge base — no manual chunking or embedding pipeline setup required.

## What Is Captain?

Captain is an automated RAG (Retrieval-Augmented Generation) solution built for developers and teams who want to plug a knowledge base into their AI apps without the usual infrastructure overhead. Upload raw files — PDFs, docs, markdown, text — and Captain handles parsing, chunking, embedding, and indexing automatically.

The pitch is simplicity: point it at a folder, wait a few minutes, query your data via API.

## Setup Workflow

### Step 1: Install Captain

```bash
# Clone the repo
git clone https://github.com/runcaptain/captain.git
cd captain

# Run the setup script
./setup.sh
```

### Step 2: Configure Your Data Source

Create a `config.yaml` pointing to your file source:

```yaml
data:
  source: ./my-docs/ # Local folder or S3 bucket
  file_types:
    - pdf
    - md
    - txt
    - docx

rag:
  chunk_size: 512
  overlap: 64
  embedding_model: bge-base-en-v1.5
```

### Step 3: Ingest and Index

```bash
captain ingest
```

This parses all files, splits them into chunks, generates embeddings, and stores them in the configured vector store (Qdrant by default, with pgvector and Milvus as options).

### Step 4: Query via API

```bash
curl -X POST http://localhost:8080/query \
  -H "Content-Type: application/json" \
  -d '{"question": "What was the Q3 revenue?", "top_k": 5}'
```

Response includes the retrieved chunks and a synthesized answer.

## Deeper Analysis

**What stands out:**

- **Zero manual chunking** — Most RAG tools make you write preprocessing scripts. Captain infers chunk boundaries from document structure (headings, paragraphs, tables).
- **Multi-format support** — Handles PDF, DOCX, Markdown, plain text out of the box. Others require converting everything to plain text first.
- **Self-hosted** — No data leaves your infrastructure. The hosted SaaS option exists, but the open-source version runs on a VPS with4GB RAM.
- **Streaming responses** — API supports Server-Sent Events for streaming answers, which matters for UX in chat interfaces.

**Where it falls short:**

- No built-in web crawler — if your "files" live on Confluence or Notion, you need to export them first.
- The vector store is swappable but the default Qdrant setup requires Docker. Single-binary deployment is not there yet.
- Embedding model is fixed to BGE by default. Swapping to OpenAI or Cohere embeddings requires a code change.

## Practical Evaluation Checklist

- File ingestion works for PDF, DOCX, MD, TXT
- Chunk quality matches document structure (not fixed byte boundaries)
- Query latency under 250ms for a1,000-document corpus on4GB RAM
- API returns source citations alongside answers
- Self-hosted option runs on a single VPS

## Security Notes

- All file processing happens locally in the self-hosted version — no data sent to third-party APIs unless you configure external embedding services.
- The API layer supports JWT authentication. Disable it for internal-only deployments at your own risk.
- No built-in audit log for which user queried which document. Add one if compliance matters.

## FAQ

**Q: Can Captain handle large documents (500+ pages)?**
**A:** Yes, but ingestion slows significantly. Documents over 200 pages should be split before ingestion for best chunk quality.

**Q: What embedding models does it support?**
**A:** Defaults to BGE-base-en-v1.5. Can be swapped to any SentenceTransformers model or OpenAI/Cohere APIs with a config change.

**Q: Is there a hosted option?**
**A:** Yes, runcaptain.com offers a hosted tier. The open-source version is fully functional and suitable for small-to-medium deployments.
