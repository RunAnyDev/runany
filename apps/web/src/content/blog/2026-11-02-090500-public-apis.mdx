> **TL;DR:** Public APIs is a collective list of free APIs, and after ten years it is still the fastest way to find a free endpoint for a side project. It is MIT licensed, holds 494,667 stars and 55,209 forks, and it gained roughly 324 stars in today's trending window. The categories cover weather, finance, geography, machine learning, entertainment and dozens more, and the repository's homepage points to the APILayer service that maintains it.

## What it is

The description is four words: "A collective list of free APIs". That is the entire pitch, and it is the right one.

The repository was created in March 2016, which makes it one of the longest-running curated lists in the open source ecosystem. It has survived multiple waves of API marketplaces, several API directories that came and went, and the shift away from free developer tiers that happened across the industry.

The topic list is `api`, `apis`, `dataset`, `development` and `free`. The `dataset` tag is the one that understates it. Most people treat this as a reference list, but the raw material is structured enough to use as a dataset, which is how you would approach it if you wanted to answer a question about the API economy rather than find one endpoint.

## Why the fork count is enormous

55,209 forks is unusual for a list of links. Most people do not fork a README of links.

The likely explanation is that people fork it to keep a personal copy, prune it, or turn it into their own list with a different structure. Some fork it to migrate to a private tracker or a spreadsheet. A sizeable share probably fork it as a test repository, since it is a well-known and completely safe target for practicing git workflows.

Whatever the reason, the fork number is a good proxy for how much people rely on it. This is not a list people bookmark once and forget. It is a list people fork.

## What you will find in it

The structure is a set of category files, each holding a list of API entries with the name, a short description, and a link. The categories that get used most often in practice tend to be the boring ones.

| Category type | Typical use |
|---|---|
| Weather and environment | Current conditions and forecasts for a location |
| Finance and currency | Exchange rates, market data, crypto prices |
| Geolocation and maps | Coordinates, geocoding, places, directions |
| Machine learning | Image and text recognition, translation, embeddings |
| Entertainment and media | Comics, movies, music, books, quotes |
| Communication and messaging | SMS, email, chat, translation |

Two things to keep in mind when you pull from it. Most of these are free tiers, not free products, and the free tiers change without notice. And a listed API is not a guarantee that the endpoint still responds. Check the API itself before you design around it.

## How to try it

Clone it and read the categories directly:

```bash
git clone https://github.com/public-apis/public-apis.git
cd public-apis
ls
```

The default branch is `master` rather than `main`, which is a small sign of the repository's age.

If you want to query it as data rather than read it, the category files are plain text and easy to parse:

```bash
# List every API named in the weather category
grep -E '^- API:' src/categories/weather.md
```

The homepage listed in the repository metadata is an APILayer referral link, so the project is maintained alongside a commercial API gateway. That does not affect the list itself, which is MIT licensed and community contributed, but it is worth knowing when you read the README.

## When to use it

Use it when you need a free endpoint for a prototype and you do not want to spend an afternoon searching for one. It is the fastest path from "I need geocoding" to a working request.

Skip it when you are building something with a real SLA. Free tiers with no commitment are exactly the endpoints that change their terms. For production, treat this list as a starting point for research, then pick a provider with an actual contract behind it.
