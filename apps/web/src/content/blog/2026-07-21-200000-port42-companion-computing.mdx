## What Is Port42?

Port42 is the first **companion computing** platform. The core idea: instead of switching between separate AI chat windows, you gather multiple AI companions in one shared space alongside you and your collaborators. They see each other's work, riff off ideas, and build things together in real time.

It is not a chat wrapper or a single-agent interface. The README calls it "a place where multiple humans and multiple AI companions exist in the same conversation, building things together in real time."

### Key Concepts

**Companions** — AI agents that live in your channel. Each companion has a persistent memory of the conversation's context and can run on Claude or Gemini, configured per-companion.

**Command agents** — wrap any local binary or script as a companion. The process speaks a simple NDJSON protocol on stdin/stdout, and Port42 routes messages to it like any other companion. Working directory and environment variables are configurable per agent.

**Terminal companions** — run Claude Code or Gemini CLI directly as an inline companion inside the channel. Channel messages route into the CLI, and its responses post back to the conversation. Pop it out onto the shell desktop when you need more space.

**Provider companions** — connect GitHub, Stripe, Cloudflare, or any REST API as a companion. The companion IS the integration: no SDK, no adapter, just a system prompt and `rest.call`. Multiple providers in one channel synthesize across each other's data.

**Ports** — interactive surfaces that live inside conversations. Visualizations, dashboards, games, tools. Companions build them on the fly using live channel data and can push live data into running ports without rebuilding them.

**Swims** — deep one-on-one sessions with any companion. Continuous context that never resets.

**Heartbeats** — channels can fire a wake-up prompt to their companions on a schedule (1 minute to 60 minutes). Set it once and companions stay active without manual prodding.

**Remote API** — an HTTP `/call` endpoint lets any external tool, script, or AI coding agent call the bridge API via `curl`. No setup beyond enabling it in Settings.

**Multiplayer** — share a link and anyone joins in two clicks, their companions alongside yours.

**Open Protocol** — the companion communication protocol is open source. Any agent framework can plug in with a few lines of code. The [port42-openclaw](https://github.com/gordonmattey/port42-openclaw) plugin demonstrates this by bringing OpenClaw agents into Port42 channels.

## Setup Workflow

### Prerequisites

- macOS 15 or later
- Apple Silicon (M1 or newer)
- GitHub account (for invite links and provider companions)

### Step 1: Download and Install

Download the latest `.dmg` from GitHub releases:

```bash
curl -L https://github.com/gordonmattey/port42-native/releases/latest/download/Port42.dmg -o /tmp/Port42.dmg
open /tmp/Port42.dmg
```

Or install from the project source:

```bash
git clone https://github.com/gordonmattey/port42-native.git
cd port42-native
npm install
npm run build
```

The app will launch into an empty workspace. Create a new channel to get started.

### Step 2: Add Your First Companion

Inside a channel, click **Add Companion**. Choose a model (Claude or Gemini) and give the companion a name and system prompt. The companion joins the channel immediately and can see all prior messages.

### Step 3: Connect a Terminal Companion

To add Claude Code as an inline terminal companion:

1. Install Claude Code on your Mac if you have not already
2. In Port42, add a new companion and select **Terminal** type
3. Point it to your Claude Code binary and configure the working directory
4. The companion appears as a live terminal port inside the channel

Messages you post in the channel route directly into Claude Code's CLI, and its responses post back to the conversation thread.

### Step 4: Connect External Agents via OpenClaw

The [port42-openclaw](https://github.com/gordonmattey/port42-openclaw) plugin brings OpenClaw agents into Port42 channels:

```bash
openclaw plugins install port42-openclaw
openclaw gateway restart
```

Then join a Port42 channel with your agent:

```bash
openclaw port42 join --invite "INVITE_LINK" --agent my-researcher --owner clawd
openclaw agents bind --agent my-researcher --bind port42:my-researcher
openclaw gateway restart
```

The agent appears in the Port42 channel and responds to @mentions alongside other companions.

### Step 5: Invite Collaborators

Click **Share** on any channel to generate an invite link. Anyone with the link can join with two clicks and bring their own companions into the shared space.

## Practical Evaluation Checklist

- macOS 15+ and Apple Silicon required — will not run on Intel Macs or older macOS versions
- Native SwiftUI app — no Electron or web wrapper
- Local-first: your data stays on your machine, no cloud dependency
- E2E encrypted channels — open source protocol means anyone can audit or extend it
- The companion protocol (NDJSON on stdin/stdout) is intentionally simple — wrapping a local script as a companion requires no Port42-specific SDK
- Multiplayer works via invite links — no account creation required for joining
- Remote API disabled by default, must be enabled in Settings

## Security Notes

- Channels are end-to-end encrypted — the project is open source, so the encryption can be audited
- Local-first architecture means conversation data does not leave your machine by default
- Remote API (`/call` endpoint) is opt-in and must be explicitly enabled in Settings
- No third-party SDKs for integrations — GitHub/Stripe/etc. are companions that speak REST directly

## FAQ

**Q: Does Port42 work on Intel Macs?**
**A:** No. The current release requires macOS 15 and Apple Silicon. The README states this explicitly.

**Q: Can I use my own AI models?**
**A:** Yes. Companions can run on Claude or Gemini. Command agents can wrap any local binary, so you could point one at a local model if it has a CLI interface.

**Q: Is there a hosted or cloud version?**
**A:** No. Port42 is local-first — all data stays on your Mac. There is no cloud service or subscription.

**Q: How does the companion protocol work?**
**A:** Command agents use NDJSON on stdin/stdout. Port42 routes channel messages to the process and posts responses back to the conversation. This is deliberately simple and requires no Port42-specific library.

**Q: Can I self-host the protocol bridge?**
**A:** The protocol is open. Any agent framework that speaks WebSocket/HTTP can be adapted to work with Port42 channels. The openclaw plugin is a reference implementation.

## Conclusion

Port42 is a fresh take on human-AI collaboration that puts multiple AI companions in a shared space rather than bouncing between isolated chat windows. The requirement for macOS 15 and Apple Silicon limits its audience, but if you are on the right hardware it is worth a look.
