## What Is xa11y?

xa11y is a cross-platform desktop accessibility library written in Rust, with Python and Rust APIs. It lets you drive native desktop applications using accessibility APIs — the same underlying system that screen readers use — rather than pixel coordinates or screenshot-based computer vision.

The key difference from tools like OmniParser or screen-capture-based agents is that xa11y reads the actual accessibility tree: a structured representation of every UI element (buttons, text fields, windows) with their names, roles, and states. This is faster, cheaper, and more reliable than sending screenshots to a vision model.

**Use cases:** end-to-end desktop testing, computer-use agents, MCP tools, assistive technology.

## Setup Workflow

### Rust

Add to your `Cargo.toml`:

```toml
[dependencies]
xa11y = "0.9"
```

### Python

```bash
pip install xa11y
```

Requires Python 3.9+. Pre-built wheels are available for Linux, macOS, and Windows.

### Permissions

**macOS:** Grant your terminal two permissions in **System Settings > Privacy & Security**:
1. **Accessibility** — required for all accessibility API access.
2. **Screen & System Audio Recording** (macOS 26+) — required to read window content. Without this, only menu bars are visible.

Restart your terminal after changing permissions.

**Linux:** AT-SPI2 must be running (default on GNOME and most desktop environments). No special permissions needed.

**Windows:** No special permissions needed.

## Core API

### Rust

```rust
use xa11y::*;
use std::time::Duration;

fn main() -> Result<()> {
    // `by_name` polls for up to the given timeout. Pass `Duration::ZERO`
    // for a single attempt with no waiting.
    let safari = App::by_name("Safari", Duration::from_secs(5))?;

    // Find elements with CSS-like selectors
    let buttons = safari.locator("button[name='Submit']").elements()?;
    println!("Found {} buttons", buttons.len());

    // Interact with elements via locator (re-resolves every call)
    safari.locator("button[name='Submit']").press()?;

    Ok(())
}
```

### Python

```python
import xa11y

safari = xa11y.App.by_name("Safari")

# Find elements with CSS-like selectors via locator
for button in safari.locator("button").elements():
    print(button.name)

# Interact with elements
safari.locator("button[name='Submit']").press()

safari.locator("text_field[name^='Search']").set_value("hello world")
```

## Selector Syntax

xa11y queries accessibility trees with CSS-like selectors:

| Pattern | Meaning |
|---|---|
| `button` | Elements with role Button |
| `button[name='OK']` | Button named exactly "OK" |
| `button[name^='Search']` | Button whose name starts with "Search" |
| `textfield[name$='Field']` | Text field whose name ends with "Field" |
| `[name='Title'][role='Window']` | Window element with name "Title" |

## FAQ

**Q: How is this different from PyAutoGUI or Pywinauto?**
**A:** PyAutoGUI uses pixel coordinates and requires the app to be in the foreground. Pywinauto targets Windows specifically. xa11y reads the accessibility tree, so it works with any app regardless of window position and is cross-platform.

**Q: How is this different from OmniParser or screen-based agent tools?**
**A:** OmniParser and similar tools use vision models on screenshots to identify UI elements — slow and expensive. xa11y reads the actual OS accessibility tree, which is a structured, text-based representation. This is faster, deterministic, and does not require GPU inference.

**Q: Can this be used as an MCP server tool?**
**A:** Yes — the README lists "MCP tools" as a primary use case. You can expose xa11y's automation capabilities as MCP tools for AI agents.

**Q: Does it work with Electron or web-based apps?**
**A:** For web content rendered in a browser, Playwright is still the better tool. xa11y targets native desktop apps where accessibility APIs are the standard UI introspection mechanism.

## Conclusion

xa11y fills a gap between screenshot-based computer vision agents and platform-specific automation tools. Its accessibility-tree approach is faster, cheaper, and more reliable than vision-based alternatives, and its cross-platform Rust core means the same codebase runs on macOS, Windows, and Linux. The Playwright-style API surface makes it easy to adopt for developers already familiar with browser automation. If you are building desktop automation or computer-use agents, xa11y is worth evaluating.
