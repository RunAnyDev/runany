## What Is Manufact?

Manufact is the company behind **mcp-use**, an open-source SDK for building MCP (Model Context Protocol) servers, clients, and agents in TypeScript and Python. The SDK is framework-agnostic and works with ChatGPT Apps, Claude Connectors, and any MCP-compatible host.

Their hosted product, **Manufact Cloud**, takes a git-push workflow: connect your GitHub repo, and the platform builds, deploys, and hosts your MCP app or server with zero cold-start configuration. The stated deployment target is under 60 seconds from push to live.

The product is structured around two layers:

**mcp-use SDK (open source, MIT)**
- TypeScript and Python support
- Build once, target ChatGPT / Claude / Gemini separately
- Templates: Chart Builder, Diagram Builder, and more
- 10.4k GitHub stars

**Manufact Cloud (hosted PaaS)**
- MCP Hosting — production deployment with auto-scaling
- Cross-client Testing — verify behavior across ChatGPT, Claude, and Gemini
- Publishing Checks — audit against ChatGPT Apps Store and Cloud Connectors requirements
- Cloud Inspector — trace, replay, and debug MCP traffic in production
- Public Chat — embeddable chat surfaces for your product
- Analytics — usage, latency, and reliability dashboards

## Setup Workflow

### Prerequisites

- Node.js 18+ or Python 3.10+
- GitHub account for Cloud deployment
- A Manufact Cloud account (free tier available)

### Step 1: Install the SDK

**TypeScript:**
```bash
npm install mcp-use
```

**Python:**
```bash
pip install mcp-use
```

### Step 2: Scaffold an MCP App or Server

Use the Manufact web builder to scaffold from a prompt, or start from a template:

```bash
npx mcp-use create chart-builder
cd chart-builder
npm install
```

### Step 3: Deploy to Manufact Cloud

Connect your GitHub repo in the Manufact dashboard, then push:

```bash
git push
```

The platform detects the push, builds the container, runs publishing checks, and makes the app live — typically in under 60 seconds.

### Step 4: Test Across Clients

Use the Cloud Inspector to trace real traffic. Use Cross-client Testing to verify your MCP app behaves correctly when called from ChatGPT, Claude, and Gemini — without maintaining three separate codebases.

## Deeper Analysis

### Cross-client parity

The most distinctive claim in Manufact's positioning is "build once, deploy to ChatGPT, Claude, and Gemini." The MCP specification standardizes the protocol, but the host implementations (Apps Store, Claude Connectors, Gemini Extensions) have subtle differences in tool schemas, permission models, and rate limits. Manufact's publishing checks are designed to catch these gaps before submission.

### mcp-use vs. building from scratch

You can implement MCP directly against the protocol spec without mcp-use. The SDK's value is in handling the boilerplate: server lifecycle management, tool registration with schema validation, streaming response handling, and client credential flows. For TypeScript projects, it integrates with familiar frameworks; for Python, it covers the async patterns the spec requires.

### The "Vibecode" builder

The Manufact web UI includes a natural-language scaffolder: describe what you want and it generates the MCP server structure. This lowers the floor for prototyping, but production servers will still need manual review of the generated code — as with any AI-scaffolded boilerplate.

### Pricing

Manufact Cloud has a free tier. Paid tiers add more concurrent deployments, traffic volume, and retention for Cloud Inspector traces. The mcp-use SDK itself is MIT-licensed and free for all uses.

## Security Notes

- MCP servers execute tools with the permissions of the calling agent — treat them as you would any privileged endpoint
- Manufact Cloud Inspector captures request/response traces; verify your trace retention settings before deploying sensitive workflows
- The SDK does not store credentials; it passes them through from the host environment (ChatGPT, Claude, etc.)

## FAQ

**Q: Does mcp-use support Python?**
**A:** Yes. The SDK has both TypeScript and Python packages on npm/PyPI.

**Q: Can I self-host instead of using Manufact Cloud?**
**A:** Yes — mcp-use is MIT-licensed and runs on any container host. Manufact Cloud is a convenience PaaS on top of the open-source SDK.

**Q: Does this work with existing MCP servers built against the raw protocol spec?**
**A:** Yes. mcp-use is compatible with any server that implements the MCP spec. Manufact Cloud can host existing MCP servers via its GitHub integration.

**Q: What hosts are supported beyond ChatGPT and Claude?**
**A:** The MCP protocol is open and any platform implementing it can host mcp-use servers. Manufact explicitly tests ChatGPT, Claude, and Gemini parity via its cross-client testing feature.

## Conclusion

Manufact solves the MCP deployment gap: writing an MCP server is well-documented, but getting it hosted, tested across clients, and published to the ChatGPT Apps Store or Claude Connectors requires glue work that Manufact Cloud automates.
