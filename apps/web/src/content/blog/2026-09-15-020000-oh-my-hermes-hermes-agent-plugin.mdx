## What It Is

Oh-My-Hermes is an add-on for the Hermes coding agent that brings a few capabilities most "agent" tools lack out of the box:

- **Long-term memory.** Persistent notes that survive across sessions, so the agent remembers project conventions, past decisions, and recurring patterns.
- **Model-optimized workflow packages.** Pre-bundled tool sequences tuned for common coding workflows — test generation, refactoring, dependency updates — so the agent doesn't have to re-discover them.
- **Curated utilities.** Helper functions and wrappers that make common operations (file diffs, code search, dependency graph traversal) less verbose to invoke.

The plugin installs into a Hermes Agent installation and extends it without forcing a fork. The project site walks through the install steps and the available workflow packages.

## Why It Matters

Most coding-agent experiences today start from a blank slate every session. The agent doesn't remember that this codebase uses tabs not spaces, that the test runner needs a Docker env, or that the user prefers concise commit messages. Each session is a re-introduction.

Long-term memory plus packaged workflows turn that dynamic around. The agent becomes more useful the longer it works with you, and common tasks stop being re-derived from scratch. The Claude Code plugin ecosystem (and similar projects for other agents) has been exploring this space; oh-my-hermes is a clean implementation of the pattern for the Hermes agent.

A few things are interesting about the design:

- **Single plugin, many capabilities.** Rather than a constellation of single-purpose plugins, oh-my-hermes ships a coordinated bundle that the user installs once.
- **MIT licensed.** Friendly to fork, adapt, and redistribute.
- **Python-native.** Aligns with the Python-heavy agent ecosystem.
- **Workflow packages as a first-class concept.** Codifying "how to refactor a module" as a packaged tool sequence is a real productivity improvement over prompting for it every time.

## Practical Trade-Offs

A few honest constraints:

- **Hermes-specific.** This is a plugin for Hermes Agent, not a general coding-agent framework. Users on Claude Code, Cursor, or Copilot will need a different plugin (or port).
- **Smaller community.** At ~2k stars, oh-my-hermes is a young project. The workflow library will grow with time, but the catalog is smaller than the more established Claude Code plugin ecosystems.
- **Memory quality is your responsibility.** Long-term memory only helps if it's structured well. Garbage in, garbage out — the agent will faithfully remember your project's quirks, including the bad ones.
- **Vendor lock-in considerations.** Some workflow packages may encode assumptions about how Hermes behaves that don't survive future updates. Pin to versions in production.

These are normal caveats for any agent plugin system. None of them are reasons to avoid oh-my-hermes if you're already on Hermes.

## Who Should Care

Oh-My-Hermes is a strong fit for:

- **Hermes Agent users** who want a more structured, memory-augmented coding experience.
- **Developers tired of re-explaining project conventions** to a coding agent every session.
- **Teams experimenting with persistent agent workflows** and looking for an MIT-licensed reference implementation.
- **Plugin authors** studying how to package long-term memory and workflow libraries for a coding agent.

If you're not on Hermes, this is a useful reference but not directly applicable. The plugin ecosystem around Claude Code and Cursor has its own equivalents with broader communities.

## Summary

Oh-My-Hermes is a focused, well-scoped plugin pack for the Hermes coding agent. The combination of long-term memory, workflow packages, and curated utilities addresses real friction in day-to-day agent use. For Hermes users, it's worth installing and trying; for plugin authors, it's a useful reference implementation of the pattern.
