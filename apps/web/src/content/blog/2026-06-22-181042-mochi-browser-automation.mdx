## What Is Mochi.js?

Mochi.js is a browser automation library built exclusively for [Bun](https://bun.sh) (≥1.1). It targets developers who need high-fidelity, stealth-capable browser automation without stitching together multiple libraries.

The core problem it solves: existing browser automation tools randomize fingerprint surfaces independently — pick a user agent, pick a hardware concurrency, pick a WebGL renderer, and hope nothing cross-references. A single probe that compares two surfaces breaks the spoof. Mochi instead derives every fingerprint surface from one `(profile, seed)` pair through a deterministic 48-rule directed-acyclic graph (DAG), so a Mac user agent is never paired with a Linux WebGL renderer.

The install command, verified from the homepage:

```bash
bun add @mochi.js/core @mochi.js/cli
bunx mochi browsers install
```

## Setup Workflow

### Step 1: Install

Mochi requires Bun ≥1.1. Install Bun first if you do not have it:

```bash
curl -fsSL https://bun.sh/install | bash
```

Then add Mochi:

```bash
bun add @mochi.js/core @mochi.js/cli
```

### Step 2: Install Chromium

```bash
bunx mochi browsers install
```

This installs a stock Chromium binary. Mochi does not bundle a patched browser.

### Step 3: Write Your First Script

```typescript
import { mochi } from "@mochi.js/core";

const session = await mochi.launch({
  profile: "linux-chrome-stable",
  seed: "user-12345",
});
try {
  const page = await session.newPage();
  await page.goto("https://httpbin.org/headers");
  console.log(session.profile.userAgent);
} finally {
  await session.close();
}
```

The `profile` argument selects a pre-built fingerprint matrix. Available profiles include:

- `linux-chrome-stable` (default for Linux servers)
- `mac-m4-chrome-stable`
- `mac-chrome-stable`
- `mac-chrome-beta`
- `windows-chrome-stable`
- `mac-brave-stable`

The `seed` string parameterizes the deterministic fingerprint generator.

## Deeper Analysis

### Relational Fingerprinting

Every fingerprint surface — canvas, WebGL, audio, fonts, MediaDevices, and WebGPU — derives from a single `(profile, seed)` pair through Mochi's 48-rule DAG. This means:

- A Mac UA is never paired with Linux WebGL (cross-surface coherence)
- All surfaces update together when the seed changes
- The Probe-Manifest harness in CI compares live session fingerprints against captured baselines and gates PRs on zero-diff

### Chromium-Native Fetch

`page.goto`, in-page `fetch`, and `session.fetch` all route through Chromium itself via CDP's `Network.loadNetworkResource` and `page.evaluate('fetch')`. This means JA4, JA3, and HTTP/2 fingerprints are real Chrome by construction — there is no parallel HTTP layer with a different TLS stack to keep in lockstep.

### Behavioral Synthesis

`humanClick`, `humanType`, and `humanScroll` synthesize behavior from biomechanical models:

- Bezier paths with overshoot and correction
- Fitts-law movement time calculations
- Lognormal digraph delays for typing

These are parameterized from the matrix's `behavior` block, controlling hand tremor, words-per-minute, and scroll style.

## Security Notes

- Mochi is a browser automation library, not a security tool. It is designed for legitimate use cases such as web scraping of anti-bot-protected sites, automated testing with realistic fingerprints, and LLM agent task execution.
- Using it to impersonate users or bypass authentication flows may violate the Target website's terms of service and applicable laws.
- The MIT license places no restrictions on use, so due diligence is the user's responsibility.
- The Linux datacenter recommendation from the project — use a Linux profile on a hosting ASN rather than spoofing Windows — reflects a sound WAF-evasion strategy: Linux is underrepresented in desktop traffic but overrepresented among real developers and researchers, so WAFs trained on real traffic do not flag it.

## FAQ

**Q: Does Mochi require a patched Chromium?**
**A:** No. It uses stock Chromium (installed via `bunx mochi browsers install`). All stealth is achieved through fingerprint derivation and routing, not browser patching.

**Q: Can it bypass Cloudflare Turnstile?**
**A:** It includes a Turnstile challenge handler with `autoClick`, `humanize`, and `onSolved` callbacks. Results depend on the specific challenge configuration and deployment environment.

**Q: Is it production-ready?**
**A:** It is at v0.9.4 as of this writing. The project ships a Probe-Manifest CI harness that gates every PR on zero-diff fingerprint checks, which is a strong signal of active quality control. Review the [Known Limits](https://mochijs.com/docs/reference/limits) page before committing to a production deployment.

**Q: Does it support Windows?**
**A:** The `windows-chrome-stable` profile exists, but testing coverage on Windows may be less complete than on macOS and Linux. The Windows profile derives from a Linux placeholder until dedicated captures land.

**Q: What is the Probe-Manifest harness?**
**A:** Captured baseline fingerprints from real devices live in the repository. Every pull request diffs the live session's Probe Manifest against the baseline; a zero-diff result is required to pass CI. Any intentional divergence requires a written rationale alongside the change.
