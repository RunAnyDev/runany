> **TL;DR:** yuliskov/SmartTube is a 33,225-star Android TV media player written in Java that hands full control over player behavior, streaming sources, and playback preferences back to the viewer, with no advertising layer or telemetry baked in.

[yuliskov/SmartTube](https://github.com/yuliskov/SmartTube) sits in the niche between stock Android TV launchers and Kodi-style power-user setups. The project page describes it as a way to "browse media content with your own rules on Android TV," and that single sentence captures the design philosophy. You install it on an Android TV box or smart TV, point it at the streaming sources you want, and configure player behavior without the restrictions a vendor app would impose.

The repo carries 33,225 stars and 2,015 forks as of this writing, with a push dated September 13, 2026. The project landing page lives at [smarttubeapp.github.io](https://smarttubeapp.github.io) and the codebase is Java with some Kotlin. Topics include `android`, `android-tv`, `android-tv-box`, `java`, `kotlin`, `retrofit2`, and `rxjava-android`, which gives you a sense of the technical stack: a native Android client built on Retrofit for HTTP and RxJava for async streaming. The license is MIT, so anyone can fork, modify, and redistribute.

What makes it interesting for non-Android developers is the configuration surface. SmartTube exposes player settings that mainstream streaming apps deliberately hide — buffer sizes, codec preferences, sponsor block markers, ad-skip rules, and dearrow preferences. If you want a media player that respects your time instead of inserting mid-roll ads every eight minutes, this is one of the most actively maintained options on Android TV. The maintainers push updates frequently, which matters because streaming service front-ends change their layouts often and a stale player breaks within weeks.

For developers, the codebase is a useful reference for building Android TV apps that have to handle long-running streaming sessions. Retrofit for API calls and RxJava for stream coordination is a tested combination, and the project shows how to structure player state across configuration changes without losing the user's place in a video. Topics tagged `rxjava-android` and `retrofit2` make it findable when you need a concrete example rather than a tutorial.

If you are evaluating SmartTube as an end user, the practical entry point is the GitHub releases page rather than an app store. The project distributes APKs directly because Google Play policies around ad-blocking media players are inconsistent. Installation is a standard sideload: enable unknown sources, install the APK, launch, and point it at your media backend. Most users pair it with a self-hosted media server or a debrid service for higher-resolution streams.

The trade-off is that SmartTube is opinionated. It does not try to be everything to everyone. If you want a polished streaming service aggregator with recommendations, a stock vendor app will serve you better. If you want to control the rules — what plays, what gets skipped, how the player behaves on your specific network — the project is built for that audience.
