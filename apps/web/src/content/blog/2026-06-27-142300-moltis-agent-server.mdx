## What Is Moltis?

Moltis is a persistent personal AI agent server built entirely in Rust. Unlike agent frameworks that require a constellation of npm packages and runtime dependencies, Moltis ships as a single binary you run on your own hardware — a Mac Mini, a Raspberry Pi, or any Linux server you control.

The project positions itself as a secure, auditable alternative to larger agent platforms. Every tool call runs inside a sandboxed container (Docker, Podman, or Apple Container), and the entire codebase is organized as a 59-crate Rust workspace (~270K lines of Rust) that you can audit module by module. The core agent loop and model interface are roughly 7.5K lines; the rest is modular provider and integration code.

Key capabilities from the official README:

- **One binary** — no Node.js, no npm, no runtime to manage
- **Sandboxed execution** — every tool runs isolated; your host never executes untrusted code
- **Multi-provider LLMs** — OpenAI, Anthropic, local models, and more
- **Voice I/O** — built-in STT and TTS providers
- **Memory** — SQLite with full-text search and vector memory for RAG-style recall
- **Built-in integrations** — Telegram, Signal, Discord, Slack, Matrix, Nostr, Microsoft Teams
- **MCP support** — stdio and HTTP/SSE transport for Model Context Protocol servers
- **Skills system** — bundled and workspace skills with autonomous improvement
- **SSH / remote exec** — connect to nodes remotely with managed deploy keys

## Setup Workflow

### Step 1: Install

Choose the method that fits your environment:

```bash
# macOS / Linux one-liner
curl -fsSL https://www.moltis.org/install.sh | sh

# macOS / Linux via Homebrew
brew install moltis-org/tap/moltis

# Docker (multi-arch: amd64/arm64)
docker pull ghcr.io/moltis-org/moltis:latest

# Build from source
cargo install moltis --git https://github.com/moltis-org/moltis
```

### Step 2: Start and Configure

```bash
# Start the server (opens web UI on localhost:13131)
moltis

# Or run with a config file
moltis --config /path/to/config.toml
```

Open `localhost:13131` in your browser, paste your LLM provider API key, and pick a model. If you use an OAuth provider such as GitHub Copilot, the setup flow handles authentication with zero extra configuration.

### Step 3: Connect a Channel

Moltis ships integrations for many messaging platforms. After configuring your provider key in the web UI, you can link channels from **Settings → Tools** — each channel appears as a live inventory entry you can enable or disable.

### Step 4: Add MCP Servers

Moltis supports MCP via both stdio and HTTP/SSE transports. Configure your MCP server endpoints in the web UI under **Settings → Tools → MCP**.

## Architecture Overview

The project is organized as a 59-crate Rust workspace. The core runtime crates (verified from the README):

| Crate | Approx. LoC | Role |
|---|---|---|
| `moltis-gateway` | 37.4K | HTTP/WS server, RPC, auth |
| `moltis-tools` | 37.0K | Tool execution and sandboxing |
| `moltis-providers` | 18.9K | LLM provider implementations |
| `moltis-agents` | 14.5K | Agent loop, streaming, prompts |
| `moltis-chat` | 14.2K | Chat engine, orchestration |
| `moltis-channels` | 34.0K | Telegram, Discord, Signal, etc. |

Feature flags let you trim the binary for constrained hardware:

```bash
# Minimal build for Raspberry Pi etc.
cargo install moltis --no-default-features --features lightweight
```

## Security Model

Moltis takes a layered approach to security (from the README and docs):

1. **Small unsafe surface** — unsafe code is confined to FFI boundaries and precompiled WASM runtimes, not the core agent loop
2. **Sandboxed tool calls** — Docker, Podman, or Apple Container isolates every tool invocation
3. **Secret handling** — API keys use `secrecy::Secret` and are zeroed from memory on drop
4. **SSRF protection** — DNS-resolved, blocks loopback/private/link-local addresses on outbound requests
5. **Origin validation** — rejects cross-origin WebSocket upgrades
6. **Hook gating** — `BeforeToolCall` hooks can inspect or block any tool invocation
7. **Supply chain integrity** — releases are signed with GPG (YubiKey), have SHA-256/SHA-512 checksums, and support Sigstore keyless attestations

Verify a release:

```bash
gh attestation verify <artifact> -R moltis-org/moltis
```

## Security Notes

- Moltis is designed to run on hardware you own. Do not expose the web UI to the public internet without a reverse proxy with TLS and strong auth in front of it.
- API keys entered in the web UI are stored via the Vault subsystem, not in plaintext config files.
- The WASM precompile layer (`moltis-wasm-precompile`) adds a small attack surface at tool execution boundaries — review the WASM fetch allowlist if you run untrusted tool sources.
- The `BeforeToolCall` hook is powerful — a misconfigured allowlist can defeat the sandbox intent. Test hook rules in a non-production environment first.

## FAQ

**Q: Does Moltis work without an internet connection?**
**A:** Yes. Once the binary is installed, Moltis runs entirely offline. Your LLM provider calls go over the internet, but the server itself and all tooling execute locally. If you configure a local model provider (Ollama, llama.cpp, etc.), the entire stack stays air-gapped.

**Q: How does it compare to Ollama for local inference?**
**A:** Ollama is a model runner; Moltis is an agent framework. Moltis can use Ollama as an LLM provider via its OpenAI-compatible API wrapper, giving you an Ollama-powered model inside a Moltis agent with full sandboxing, memory, and channel integrations.

**Q: Can I self-host it on a Raspberry Pi?**
**A:** Yes. Use the lightweight feature flag: `cargo install moltis --no-default-features --features lightweight`. The full Docker image also supports arm64, so `docker pull ghcr.io/moltis-org/moltis:latest` works on a Pi 4 with Docker installed.

**Q: What LLM providers are supported?**
**A:** OpenAI, Anthropic, Google Gemini, and any OpenAI-compatible API endpoint (including local providers like Ollama). Specific provider availability is in `moltis-providers` crate documentation.

**Q: Is there a hosted or managed version?**
**A:** No — Moltis is fully self-hosted. There is no cloud offering, no account required, and no telemetry sent anywhere. Everything runs on your machine.

## Conclusion

Moltis fills a specific niche: users who want a full-featured, persistent AI agent on their own hardware without assembling it from npm packages. The Rust foundation gives it a small attack surface and predictable performance, while the 59-crate modular architecture makes it auditable in a way that Node.js agent frameworks rarely are.

The sandboxed execution model is the headline feature for security-conscious deployments — every tool runs isolated, your API keys never leak through tool output, and the `BeforeToolCall` hook gives you programmatic control over what the agent can do. If that threat model matches your use case, Moltis is worth a weekend evaluation on a spare machine.
