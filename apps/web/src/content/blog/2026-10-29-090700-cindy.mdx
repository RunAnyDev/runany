> **TL;DR:** Cindy is an Apache-2.0 AI agent built in TypeScript, published with English and Chinese documentation side by side. It has 8,140 stars and 2,157 open issues, which is the number worth thinking about.

## What it is

The description is bilingual in the same way the repository is: "Consider it done. The open-source AI agent that works out of the box", followed by the Chinese equivalent, "开源、开箱即用的 AI Agent".

That is not a translated afterthought. The repository carries parallel files for most of its governance documents:

```text
README.md
README.zh-CN.md
CODE_OF_CONDUCT.md
CODE_OF_CONDUCT.en.md
SECURITY.md
SECURITY.en.md
CLAUDE.md
AGENTS.md
DESIGN.md
REVIEW.md
DCO
```

Two READMEs and two sets of conduct and security policies, in both languages, maintained in the same tree. A project that keeps both copies in sync is making a real commitment to a bilingual audience rather than running an English-first repository with a translated one.

## The governance files are unusually thorough

`DCO` is the Developer Certificate of Origin, and its presence means every contributor signs off that they have the right to submit the code. There is a `.githooks` directory to enforce it and a `CODE_OF_CONDUCT` in both languages.

`SECURITY.md` in two languages is the file you want to find in a project that asks people to run agentic code on their machines.

`DESIGN.md` and `REVIEW.md` are less common. A design document records what the system is supposed to do, and a review document records how changes to it get checked. Both being checked into the repository means the project publishes its process, not only its output.

There is also a `NOTICE` file, which usually accompanies a dependency set that requires attribution, and `.easignore`, `.npmrc`, and `.nvmrc` for the build and runtime side.

## What the issue tracker says

2,157 open issues against 8,140 stars is the number that stands out, and it is worth taking apart rather than reading as a verdict.

The repository is 531 megabytes, which puts it in a different weight class from most TypeScript agent projects. The topic list includes `android` alongside `claude-code` and `codex`, so this is a project that spans a mobile client and multiple coding agent backends. A large open issue count is consistent with that much surface area, and with a project created in late July 2026 that is still taking shape.

What the number does not tell you is the quality of the individual issues, and it is a real signal for anyone considering adoption: check the tracker for the categories that recur. If you see the same class of report repeatedly, that is the friction you will hit too.

## How to try it

```bash
git clone https://github.com/makecindy/cindy.git
cd cindy
```

The project site is cindy.app. There is no install command here, because the repository metadata does not state one and guessing at the package name would be worse than leaving it out. The `.nvmrc` file at the root is the pinned Node version to start from.

## When to use it

If you want to see how a bilingual, Apache-2.0, agent-first product is put together, the governance layer is the part to read. The design document, the review document, and the paired conduct policies are a template worth borrowing regardless of whether you ever run the agent.

It is also a reasonable reference for the multi-backend shape: topics covering Claude Code, Codex, and Android in one repository tells you the client and the backends are meant to be separable.

## When not to use it

Apache-2.0 gives you the patent grant and permissive reuse, which is the good news. The issue count is the caution. On a repository this young, with this much surface area, you are going to hit rough edges, and the tracker is the best available map of where they are.

Also weigh the size. Half a gigabyte for a TypeScript agent project is a signal that a lot ships in the box, which matches the "works out of the box" pitch and also means you should look at what is in there before you run it.
