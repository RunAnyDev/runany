## What Is Port42?

Port42 is a macOS-native AI companion app built around the idea of **persistent, multi-tool agents**. Unlike chat-based AI tools that start fresh each conversation, Port42 gives AI agents running context across your terminal, code editor, browser, and local files — letting them observe, reason, and act over extended sessions.

The app positions itself as "companion computing" — think of it as a developer-focused alternative to generic chat AI, with deep OS-level integration.

Key differentiators:
- **Native macOS app** (not a web app or Electron wrapper)
- **Multi-tool agents** — agents can browse the web, read/write files, execute shell commands
- **End-to-end encrypted** local storage
- **Open source** core engine

## Setup Workflow

### Step 1: Install Port42

Download the macOS app from the official site or via Homebrew:

```bash
brew install --cask port42
```

Alternatively, download the `.dmg` directly from [port42.ai](https://port42.ai).

### Step 2: Configure Your API Key

On first launch, Port42 prompts for an LLM API key. It supports:

- OpenAI (GPT-4o, GPT-4o Mini)
- Anthropic (Claude 3.5 Sonnet, Opus)
- OpenAI-compatible endpoints (Ollama, LM Studio, etc.)

```bash
# Set via the app UI (Settings → API Keys)
# Or use environment variables for local models
export OPENAI_API_KEY="sk-..."
```

### Step 3: Enable Tool Integrations

Port42's agent capabilities come from its tool stack. Enable the ones you need from **Settings → Integrations**:

- **Terminal** — read/write/execute shell commands
- **File System** — read and write local files
- **Browser** — web browsing via a built-in browser context
- **Code Interpreter** — execute code snippets and return results

### Step 4: Start a Session

Create a new project session and introduce your task:

```
> I want to build a REST API endpoint that validates 
> incoming webhooks and writes them to a SQLite DB.
```

The agent will propose steps, ask clarifying questions, and execute across tools as needed.

## Deeper Analysis

### Architecture

Port42 uses a modular agent loop:
1. **Context gathering** — agents read from enabled tool contexts
2. **Reasoning** — LLM-driven planning step
3. **Action** — tool calls (file I/O, shell, browser)
4. **Reflection** — agent reviews output and decides next step

This is similar to Devin or Cursor Agent but focused on macOS native integration rather than cloud-hosted agents.

### Tool Quality

The browser tool uses a headless browser context, which means it can interact with SPAs and JavaScript-heavy sites. File system access is scoped to project directories by default.

### Privacy Model

Port42 stores conversation history and context locally, encrypted with a user-controlled key. API calls go directly to your chosen provider — Port42's servers don't proxy LLM traffic (if using self-hosted or API key-based providers).

## Practical Evaluation Checklist

- Native macOS app (not Electron) — performance and integration benefits
- Multi-turn agent sessions with persistent memory
- Tool suite covers shell, files, browser, code execution
- End-to-end encrypted local storage
- Open source core engine
- API key flexible (supports OpenAI, Anthropic, Ollama)

## Security Notes

- **API keys** — stored locally, encrypted at rest. Never sent to Port42's servers when using self-hosted models.
- **Tool permissions** — each integration requires explicit opt-in. Agents can't silently access your full filesystem.
- **Code execution** — shell commands run under the same user as the app. Scope permissions to project directories.
- **Open source** — core engine is auditable at [github.com/port42/port42](https://github.com/port42/port42)

## FAQ

**Q: Is this different from using Claude Code or Cursor Agent?**
**A:** Yes — Port42 is a native macOS app rather than a VS Code extension or cloud service. It persists agent context across sessions on your local machine, and its tool stack is designed for long-running collaborative workflows rather than per-file edits.

**Q: Can I use my own models (Ollama, LM Studio)?**
**A:** Yes. Port42 supports OpenAI-compatible endpoints, so any local model that exposes an OpenAI-compatible API works out of the box.

**Q: Does it work on Linux or Windows?**
**A:** Currently macOS only. Linux and Windows are listed as planned but not yet available.

**Q: Is the codebase open source?**
**A:** The core engine is open source. The macOS app has both open source and proprietary components.
