## Two links that point at different things

The description sends you to deeptutor.info. The `homepage` field in the GitHub API points somewhere else entirely: `http://arxiv.org/abs/2604.26962`. That is an arXiv abstract, not a product page.

The identifier itself is worth reading. arXiv IDs encode year and month in the first four digits, so 2604 means April 2026. A project created in late December 2025 shipping a paper seven months later fits a research group that treats the code as an artifact of the work.

So there are two entry points: a live web product and a paper. Which one you want depends on whether you are looking to use the tutor or to read the method behind it.

## The repository is engineered like a real service

The root directory reads like a Python service built by people who have shipped one before:

| Signal | File |
| --- | --- |
| Container build | `Dockerfile`, `Dockerfile.runner` |
| Expected configuration | `.env.example` |
| Layer boundaries | `.importlinter` |
| Secret scanning baseline | `.secrets.baseline` |
| Commit hooks | `.pre-commit-config.yaml` |
| Citation metadata | `CITATION.cff` |
| Agent packaging | `SKILL.md` |
| Third-party notices | `THIRD_PARTY_NOTICES.md` |

An import linter and a detect-secrets baseline are not things you add to a demo. They are what you add when a codebase has enough import edges to tangle and enough configuration to leak.

The `SKILL.md` file at the root is the other interesting one. DeepTutor is packaged so that a coding agent can install it as a skill, which is why `clawbot` and `cli-tool` appear in the topics list. The tutoring system is meant to be driven by an agent, not only by a human at a prompt.

## How to try it

```bash
git clone https://github.com/HKUDS/DeepTutor.git
cd DeepTutor
```

There is deliberately no install command here. The repository ships a Dockerfile and a `.env.example`, and the example environment file is where the expected configuration surface is documented. The project site at deeptutor.info is the other place to start if you would rather not read the tree first.

## When to use it

The fit is a tutoring workflow where the learner state has to persist across sessions. Lifelong personalization only means something if the system remembers, and the presence of an interactive learning topic alongside a deep research one suggests a research-then-teach loop rather than a single-shot answer.

If you are building agent tooling, the `SKILL.md` at the root makes this a reference implementation for how to package a tutoring capability so that another agent can invoke it.

## When not to use it

The fork count is close to 12 percent of the star count, and the open issue tracker has 210 entries on a ten month old repository. That is a project with real usage and real friction at the same time. Read the issue list before you commit to it.

Also note the license is Apache-2.0 rather than MIT. If you plan to build on top of DeepTutor in a product, the patent grant and the notice requirements are worth understanding before you do.
