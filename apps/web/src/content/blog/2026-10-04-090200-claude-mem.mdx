> **TL;DR:** claude-mem is a TypeScript project that records what your coding agent did during a session, compresses that record with AI, and injects the relevant parts back into later sessions. It is built to work across Claude Code, OpenClaw, Codex, Gemini, Hermes, Copilot, and OpenCode. At 95,605 stars it has crossed into mainstream territory for agent tooling.

## What it claims to do

The project description frames the problem plainly: an agent loses its memory when a session ends, so the next session starts cold. claude-mem sits in between. It captures everything the agent does while a session runs, compresses that history with AI, and feeds the relevant slice back into future sessions.

The second half of that claim matters more than the first. Writing a log is easy. Deciding which fragment of yesterday's work matters for today's task, and getting that decision right often enough to be worth the tokens, is the hard part. The compression step is where this project puts its weight.

The agent list in the description is the other thing to notice. This is not a Claude Code extension with a friendly name. It is positioned as harness-agnostic, and the topics confirm that framing, listing `anthropic` alongside generic entries like `ai-agents` and `ai-memory`.

## When to reach for it

It fits if you run coding agents across more than one harness and keep hitting the cold-start problem, where each new session re-derives project context that an earlier session already established. It also fits if you want the memory layer to be independent of whichever tool happens to be trending that month.

The Apache-2.0 license is worth noting for anyone planning to run this in a company environment. Compared with the MIT license many comparable tools ship under, Apache-2.0 carries an explicit patent grant and more specific redistribution terms, so read it before you wrap it in a product.

## When to skip it

Skip it if you work in a single harness and your sessions are short. The problem it solves does not bite as hard when you are not paying to re-establish context, and adding a capture-and-retrieve layer is overhead in that case.

Also weigh the obvious cost before adopting anything that records every action your agent takes. You are building a searchable history of your codebase work, and where that history lands on disk, how long it persists, and who can read it are questions to answer before you turn it on, not after.
