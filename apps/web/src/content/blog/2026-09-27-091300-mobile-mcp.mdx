> **TL;DR:** Mobile MCP is the Apache-2.0, TypeScript Model Context Protocol server that lets AI agents drive iOS, Android, emulators, simulators, and real mobile devices. The repository has 7.4K stars and 43 open issues since March 2025.

## What it is

The repository `mobile-next/mobile-mcp` ships a Model Context Protocol server aimed at mobile automation and scraping. The official description spells out the surface directly: "Model Context Protocol Server for Mobile Automation and Scraping (iOS, Android, Emulators, Simulators and Real Devices)." That sentence is the precise scope and the precise claim at the same time.

TypeScript is the language, Apache-2.0 is the license, and the project's homepage sits at `mobilenext.ai`. Owner is the `mobile-next` GitHub Organization.

## How to try it

The on-ramp for a Model Context Protocol server follows the standard MCP pattern:

1. Install the package on a host that can talk to either an iOS Simulator, an Android emulator, or a USB-attached real device.
2. Start the MCP server pointing the host's MCP client (Claude Desktop or a similar agent runtime) at the server's local socket.
3. Verify the agent can discover the available tools, then issue a small automation request against the simulator first.
4. Only after the simulator path is reproducible, switch the host to a real device and confirm the same calls still work end-to-end.

The "physical, real" topics imply the server handles both the deterministic simulator path and the more variable real-device path, and that second path is where most first-day surprises surface.

## When to evaluate Mobile MCP

Pick Mobile MCP when the team is wiring an AI agent into a mobile workflow and wants the device-driving layer to live inside a canonical MCP server rather than a custom integration per project. The MCP integration matters most when multiple agents in the team share the same automation host.

Skip it when the team only needs a one-off mobile automation script. The MCP framing only pays off once multiple clients, agents, or sessions need to share device-driving privileges.

## Configuration surface

Configuration is split between the MCP server's own settings (which devices and emulators to expose) and the MCP client's tool-permission configuration. Either side can be the bottleneck, depending on whether the host is multi-tenant.
