## What Is Context.dev?

Context.dev is a YC S26-launched web scraping API designed from the ground up for AI agent workflows. Instead of building and maintaining your own scraper — dealing with JavaScript rendering, rate limits, blocked IPs, and HTML parsing — you send a single REST call and get back clean, structured data ready for an LLM context window.

The product is from **Laal Shahtaan**, who posted the launch on HN:

> "Built Context.dev to solve a problem we kept hitting: getting reliable web data into agents without spending days on scraper maintenance."

The core API gives you three output modes per URL:

- **Markdown** — clean text stripped of navigation, ads, and boilerplate
- **HTML** — raw HTML if you need to parse it yourself
- **Structured JSON** — extract specific fields via JSON schema (e.g. "get me the price and rating from this product page")

Beyond single-URL scraping, Context.dev also handles **full-site crawls** and **sitemaps**, and provides **brand data** (logos, color palettes, fonts, social links) for any domain.

## Setup Workflow

### Step 1: Get an API Key

Sign up at [context.dev](https://www.context.dev) with a work email. The free tier includes 500 API credits at 30 requests/minute with no credit card required. Paid plans start at $25/month for higher limits.

### Step 2: Install the SDK

```bash
# Node.js
npm install @context.dev/context-dev-sdk

# Python
pip install context-dev
```

### Step 3: Make Your First API Call

```bash
curl -X POST https://api.context.dev/scrape \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "url": "https://news.ycombinator.com",
    "format": "markdown"
  }'
```

The response contains the scraped content, metadata, and any structured fields you defined via JSON schema.

### Step 4: Extract Structured Data

Define a JSON schema to pull specific fields from a page:

```bash
curl -X POST https://api.context.dev/extract \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "url": "https://example.com/product",
    "schema": {
      "fields": [
        {"name": "price", "selector": ".product-price"},
        {"name": "title", "selector": "h1"},
        {"name": "rating", "selector": ".rating"}
      ]
    }
  }'
```

## Deeper Analysis

### What Makes It Different

Most scraping APIs give you HTML or a raw DOM dump. Context.dev is purpose-built for the AI agent pattern:

- **Structured extraction via JSON schema** — instead of post-processing HTML, you define the fields you want upfront and get clean JSON back
- **Brand data endpoint** — one call gets logos, color palettes, fonts, social links, and company metadata for any domain, useful for building agent personas or comparison tools
- **Full-site crawl support** — the sitemap and crawl endpoints handle pagination automatically, unlike naive `curl` loops
- **Agent-focused design** — Laal specifically mentions switching from Firecrawl and migrating an entire knowledge base in under a day

### Pricing

## FAQ

**Q: Does Context.dev render JavaScript (SPA support)?**
**A:** The documentation does not explicitly mention JavaScript rendering. For SPAs that require JS execution to render content, you may need a headless browser solution like Puppeteer separately.

**Q: What's an "API credit"?**
**A:** Each API call consumes one or more credits depending on the endpoint and response size. The free tier provides 500 credits; the $25 plan provides higher limits.

**Q: Can I extract data from authenticated pages?**
**A:** Context.dev targets public web data. Authenticated pages are not supported by design.

**Q: How does it compare to Firecrawl?**
**A:** Context.dev adds structured JSON schema extraction and brand data APIs that Firecrawl lacks, at a slightly higher starting price. Both offer markdown output and site crawls.

## Conclusion

Context.dev fills a specific niche: AI agents that need reliable, structured web data without building scraper infrastructure. The JSON schema extraction and brand data endpoints are genuinely useful for agentic workflows, and the $25/month entry point is reasonable for production use. The main caveat is the lack of JS rendering support — for SPAs you still need headless browser tooling. If you need structured data from the open web in an agent loop, it's worth a look.
