> **TL;DR:** marketingskills turns marketing practice into agent-readable skills covering conversion rate optimization, copywriting, SEO, analytics, and growth engineering. MIT licensed with 52,424 stars and 7,879 forks, written in JavaScript and pushed today.

## What it is

The description reads like a package manifest: "Marketing skills for Claude Code and AI agents. CRO, copywriting, SEO, analytics, and growth engineering."

Five domains, one repository, and the output format is a skill rather than a library. That means there is nothing to import and no API surface. The value is in the text, which is the part a coding agent can read and follow while it writes or reviews something.

The most interesting word in that list is growth engineering. The other four are recognizable disciplines with published playbooks. Growth engineering is a job function that most teams invented internally over the last five years, which means there is no standard reference text to copy from. Someone had to write the guidance down.

The open issue count is worth a second look. Forty-seven open issues against 52,424 stars is a very low ratio for a project this size, and it suggests either that the maintainer is triaging aggressively or that most adoption is passive, where people copy the skills and never open anything.

## What the fork count implies

Seven thousand eight hundred seventy-nine forks is fifteen percent of the star count. For most projects that number is noise. Here it is the product working as designed, because a skill gets installed by copying its files into your own agent configuration directory.

A fork is a private copy with a public URL attached, which is exactly the right primitive for that. The consequence is the usual one: a forked copy does not receive upstream fixes, and marketing guidance goes stale in predictable ways. A pricing model that changed last quarter can still be described correctly in a fork from eight months ago.

If you install this way, plan on re-syncing rather than treating your fork as a permanent dependency.

## How to try it

The project homepage is marketing-skills.com, which is the place to see what is actually in the bundle before you commit to it. Read the skill list, then check the repository facts yourself:

```bash
gh api repos/coreyhaines31/marketingskills \
  --jq '{stars: .stargazers_count, license: .license.spdx_id,
         topics: .topics, pushed: .pushed_at}'
```

The topics list is three entries long: claude, codex, marketing. Naming Codex alongside Claude is the signal that the author is aiming at a specific subset of agent harnesses rather than at the ecosystem in general, so verify the format matches your setup before copying files across.

## When to skip it

Skip it if you need analytics or paid acquisition tooling. The declared topics include no advertising platform, no ad network, and no attribution vendor, and there are no marketing-specific topics at all beyond the bare word marketing. This is guidance text, not an integration layer. Anything that requires calling Segment, writing a variant test, or reading a campaign dashboard is outside what the repository metadata describes.

Skip it if you are after a metrics system. Analytics appears in the description as a subject the skills talk about, not as a data pipeline you install. Nothing in the metadata suggests a collector, a warehouse, or a dashboard.
