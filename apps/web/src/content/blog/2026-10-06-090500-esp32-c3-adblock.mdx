> **TL;DR:** esp32-c3-adblock puts a network-wide DNS ad-blocker on a 2 dollar ESP32-C3 with no PSRAM. It fits 537,000 domains into flash as 40-bit FNV-1a hashes, binary searches them at query time, and serves a web dashboard alongside the sinkhole.

## What the project is

Pi-hole is the reference point here, and the pitch is that the class of appliance usually needs a mini PC is now a 2 dollar microcontroller. The published topics confirm the framing: `dns`, `dns-sinkhole`, `adblocker`, `esp32`, `esp32-c3`, and `arduino`.

The constraint that shapes the entire design is the chip it targets. The description specifies no PSRAM, which on an ESP32-C3 means the usual trick of offloading a hash table to external memory is unavailable. Everything has to fit in internal memory and flash.

## How the domain list fits

The description states 537,000 domains stored as 40-bit FNV-1a hashes, binary searched. That arithmetic is worth doing, because 40 bits is five bytes:

```text
537,000 domains x 5 bytes = 2,685,000 bytes (about 2.56 MiB)
```

So the whole blocklist is a sorted array of five-byte values living in flash, with no strings and no per-entry structure. Query time becomes a binary search over that array, and the cost of a lookup is logarithmic in the number of domains rather than proportional to it.

FNV-1a is a fast non-cryptographic hash, which is the right trade here. You are not defending against an attacker choosing colliding domains, you are shrinking a list. A 40-bit truncation also makes collisions vanishingly unlikely at this scale, roughly one in a trillion per comparison.

The sinkhole is described as UDP. That is worth testing deliberately on your own network, because DNS-over-HTTPS and DNS-over-TLS clients will bypass a plain resolver entirely, and large responses that need TCP are a different code path than the one described.

## When to use it

It makes sense when you want ad blocking for every device on a network and would rather not dedicate a small server to it. The whole point is that the hardware costs less than the enclosure.

It is also worth reading as an embedded case study. Constraining a 537,000 entry lookup into five bytes per entry on a part without PSRAM is a clean demonstration of what a sorted array and a good hash can do under a hard memory budget.

## When NOT to use it

Do not expect Pi-hole's feature surface. The description names a domain list, a UDP sinkhole and a dashboard. Anything beyond that, including per-client stats, query logging at volume, regex rules, or group management, is not claimed by the project.

If your devices are configured for DNS-over-HTTPS, a UDP-only resolver will not catch their queries no matter how large your blocklist is.

And if you already run a Raspberry Pi with Pi-hole, this trades capability for a smaller power draw, not the other way around.
