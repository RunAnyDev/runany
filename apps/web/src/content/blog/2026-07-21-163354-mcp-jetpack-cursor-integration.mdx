## TL;DR

> **TL;DR:** MCP Jetpack is a single MCP server that acts as a router to 15+ services (GitHub, Linear, Atlassian, Notion, etc.) — giving Cursor AI access to all of them without installing separate servers or hitting the 50-tool limit.

## What Is MCP Jetpack?

MCP Jetpack solves two problems with MCP in Cursor AI: **setup friction** and **tool count limits**.

Normally, connecting Cursor to GitHub requires finding the right MCP server, installing it, configuring authentication, and repeating that for every service. MCP Jetpack collapses this into a single server that auto-discovers and executes the right tools behind the scenes.

For developers who want Cursor to have context about their GitHub issues, Linear tickets, or Notion pages, the traditional path means installing multiple MCP servers — each adding dozens of tools. Cursor warns that more than 50 MCP tools degrades performance. GitHub's MCP server alone registers 74 tools.

MCP Jetpack exposes all connected services through just two tools: `FindTool` and `ExecTool`. The server routes requests to the right underlying service automatically.

## How It Works

### Connecting to Cursor

Add MCP Jetpack to Cursor's MCP settings. After that, ask Cursor to interact with any connected service — GitHub, Linear, Atlassian, Notion, and others — directly from the chat.

On the first interaction with a service that requires authentication, Cursor prompts for login. Once authenticated, subsequent requests go through automatically without context switching.

### The Tool Limit Workaround

| Approach | Tools Added | Services Covered |
|---|---|---|
| Individual MCP servers | 50+ (Cursor warning threshold) | 1 each |
| MCP Jetpack | 2 (`FindTool`, `ExecTool`) | 15+ |

## Why It Matters

MCP's promise is a universal tool layer for AI assistants. The friction has been installing and managing dozens of servers and keeping authentication fresh. MCP Jetpack reduces the operational overhead to a single connection point.
