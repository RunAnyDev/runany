> **TL;DR:** Hallmark is a design review skill for Claude Code, Cursor, and Codex, packaged under the MIT license with 40,798 stars and 2,114 forks. The repository ships the skill, a set of reference docs, an evaluation harness, and a marketing site.

## What it is

The description is a single sentence: "Anti-AI-slop design skill for Claude Code, Cursor, and Codex."

That sentence is a positioning claim worth unpacking. The skill is not a code generator. It is a reviewer. It reads what an agent built and tells the agent what is wrong with it, and the target of that review is a recognizable set of bad habits: generic AI output that looks competent and says nothing.

The interesting part is that the same author who writes the skill also wrote the site that sells it. The repository has a `site/` directory and a `vercel.json`, and the homepage field points at usehallmark.com.

## The repository is more than a prompt file

```text

```

The `skills/hallmark/SKILL.md` is 18,239 bytes, which puts it in the same weight class as other design instruction documents in this category. The three sibling directories are what make this a project rather than a document.

- `references/` holds the supporting material the skill cites, so the main file stays readable and the detail loads on demand.
- `scripts/` suggests deterministic checks that run rather than opinions that get phrased differently each time.
- `agents/` implies subagent roles, where each role handles one slice of the review.

Then there is `eval/`, which is the part most skill repositories skip. If you want to claim a skill catches AI slop, you need a way to show it catching AI slop. An evaluation harness is how you turn a subjective claim into something you can measure across prompt changes.

## How to try it

```bash
git clone https://github.com/Nutlope/hallmark.git
cd hallmark
ls skills/hallmark
```

The `.claude-plugin/` directory at the root is the install path for Claude Code, and the same `skills/` layout used by other skill collections works with other agents. There is a `package.json` in the repository, so the site can be run locally as well, though the skill itself does not need a build step.

## When to use it

The case for it is a review gate rather than a generator. If your pipeline already produces pages and you suspect they read like everything else an agent wrote, this is the layer that checks the output instead of the model that produced it.

The `eval/` directory makes it more interesting than a prompt collection. If you are building internal skills, it is a reasonable reference for how to set up your own quality checks so that a skill change can be measured instead of argued about.

## When not to use it

Forty thousand stars does not mean the review will agree with your taste. Design review tools inherit the taste of whoever wrote them, and taste is exactly the thing that varies between teams and between products.

Also, MIT is permissive but the reputation claim is unverified by anything in the repository metadata. The 67 open issues and the presence of a `ROADMAP.md` both suggest the project is still moving, so pin the version you adopt and re-check after upgrades.
