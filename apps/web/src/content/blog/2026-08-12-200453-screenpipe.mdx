## What Is Screenpipe?

Screenpipe (YC S26) turns your computer into a personal AI that remembers how you actually work. It captures what you see, say, and do — locally, 24/7 — then stores everything on your machine. From that raw recording, it builds searchable memory that AI agents can query at runtime.

The core claim from the README:

> screenpipe remembers how you actually work

Unlike cloud-based context providers (Rewind, Gong, etc.), Screenpipe runs entirely on-device. No recording leaves your machine unless you explicitly pipe it somewhere. The company calls this a "local-first context layer for AI agents."

### Key features (verbatim from README)

- **Remember everything** — never forget what you saw, heard, or did
- **Run agents that work based on what you do** — pipes are agents triggered by your work activity
- **Search with AI** — find anything using natural language
- **100% local** — your data lives on your machine only
- **Source-available** — inspect, modify, audit (LICENSE.md)

## Setup Workflow

Screenpipe supports macOS (Apple Silicon + Intel), Windows, Windows ARM, and Linux.

### Step 1: Download and install

Head to [screenpipe.com/how-to-install](https://screenpipe.com/how-to-install) and select your platform. The page detects your OS automatically and serves the correct binary.

```bash
# After download, verify the binary is executable
screenpipe --version
```

### Step 2: Grant screen and audio permissions

On first launch, Screenpipe requests permission to record your screen and capture system audio. Both are required for full functionality.

- **macOS**: System Settings → Privacy & Security → Screen Recording + Microphone
- **Windows**: Windows Settings → Privacy & Security → Screen capture + Microphone
- **Linux**: Uses `wayland ScreenCast` or X11 `x11grab` depending on your compositor

### Step 3: Start recording

```bash
# Start screenpipe daemon (runs in background)
screenpipe &

# Check status
screenpipe status
```

By default, recordings are stored locally at `~/.screenpipe/`.

### Step 4: Query your memory (CLI)

```bash
# Natural language search across your screen history
screenpipe search "what did I work on yesterday at 3pm"

# List recent recordings
screenpipe recordings --since 1h
```

### Step 5: Connect an AI agent (MCP)

Screenpipe exposes an MCP server endpoint. You can point any MCP-compatible client at it to stream context to an AI agent.

```bash
# Start the MCP server on localhost:18789
screenpipe --mcp-server --port 18789
```

In your agent config, add the Screenpipe MCP server:

```json
{
  "mcpServers": {
    "screenpipe": {
      "command": "screenpipe",
      "args": ["--mcp"]
    }
  }
}
```

From there, the agent can call `screenpipe_search` to retrieve relevant clips from your recording history before taking an action.

## Deeper Analysis

### How the pipe system works

"Pipes" are Screenpipe's agent primitive. A pipe is a small program that watches your screen/audio stream and triggers when a pattern matches. Think of it as an if-this-then-that for your work activity:

```bash
# Example pipe: notify when you switch to a specific app
screenpipe pipe create --trigger "app:slack" --action "log timestamp"
```

Pipes run locally inside the Screenpipe process, so they have low latency access to the recording stream.

### Built-in PII detection

Screenpipe ships a custom PII model that runs at 9ms on consumer hardware. The [screenleak](https://screenpipe.github.io/screenleak/) project claims it outperforms Google, Microsoft, and OpenAI models on computer recording data. When enabled, it can auto-redact sensitive content (credit card numbers, credentials, etc.) from the stored recordings.

This is a meaningful differentiator for enterprise users who need compliance with GDPR, HIPAA, or SOC 2 but want the full recording capability.

### Privacy model

Because everything is local, Screenpipe sidesteps the trust problem that cloud recording tools face. Your employer, IT department, or the tool vendor never sees your raw footage. The data never leaves `~/.screenpipe/` unless you explicitly pipe it somewhere.

The license does impose restrictions: free tier covers personal use and 7-day evaluation at organizations. Teams and commercial deployments require a subscription.

## FAQ

**Q: Does Screenpipe work with Hermes Agent?**
**A:** Screenpipe has a `hermes-agent` topic on GitHub, meaning it is designed to integrate with Hermes-compatible agents via the MCP protocol. The integration requires starting the Screenpipe MCP server and adding it to your agent's MCP configuration. Full compatibility depends on the specific Hermes setup.

**Q: How much disk space does 24/7 recording use?**
**A:** This depends heavily on resolution, frame rate, and compression settings. Screenpipe compresses recordings on-device, but exact storage estimates are not published. Check `~/.screenpipe/recordings/` after 24 hours of your typical workload to calibrate.

**Q: Can I exclude specific windows or apps from recording?**
**A:** The README does not document a per-app exclusion feature. If you need selective recording (e.g., exclude banking apps), this would require reviewing the pipe configuration or the source-available code for privacy controls.

**Q: What audio sources does it capture?**
**A:** Screenpipe captures system audio and microphone input. The exact behavior depends on the platform audio subsystem (CoreAudio on macOS, WASAPI on Windows, PulseAudio/pipewire on Linux).
