## What Is LANCommander?

LANCommander is an open-source, self-hostable digital game distribution platform. Host your own game library on a server on your local network, and let players browse and install games through a desktop launcher — no internet connection needed.

The primary use case is LAN parties where internet access is unavailable or unreliable, but the platform works anywhere you want a private, self-controlled game distribution system.

The project is built with ASP.NET (server), a cross-platform .NET launcher, and a dedicated Windows packager tool. Game metadata (covers, icons, backgrounds) is automatically fetched from IGDB and SteamGridDB.

## Setup Workflow

### Option 1: Docker (Recommended)

A Docker image is available on Docker Hub. This is the fastest path to a running server.

```yaml
services:
  lancommander:
    image: lancommander/lancommander:latest
    container_name: lancommander
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Etc/UTC
      # Optional: install SteamCMD inside the container
      # - STEAMCMD=1
      # Optional: install WINE for Windows game compatibility
      # - WINE=1
    volumes:
      - /path/to/app/data:/app/Data
    ports:
      - 1337:1337/tcp   # Web admin interface
      - 35891:35891/udp # UDP beacon for server discovery
      - 213:213/udp     # IPX relay
    restart: unless-stopped
```

All game archives and configuration are stored in `/app/Data` inside the container.

To enable the optional SteamCMD (for Steam game packaging), set `STEAMCMD=1`. Cached credentials persist in `/app/Data/Steam` across restarts.

### Option 2: Standalone Binary

Download the latest release for your OS from the [Releases page](https://github.com/LANCommander/LANCommander/releases). The server is a self-contained .NET binary with no external runtime dependencies beyond a supported OS.

| Component | Windows | Linux | macOS |
|-----------|:-------:|:-----:|:-----:|
| Server    | x64, arm64 | x64, arm64 | x64, arm64 |
| Launcher  | x64, arm64 | x64, arm64 | x64, arm64 |
| Packager  | x86     | -     | -     |

The Windows launcher is the primary development target. Linux and macOS builds are provided but may have limited functionality.

### Option 3: Packager Tool (Windows Only)

To create game packages for your server, use the dedicated Packager tool (Windows only). It includes:

- Step-by-step packaging wizard
- Automatic metadata lookup from IGDB
- Registry capture for tracking installer changes
- Installer monitoring to record all file and registry modifications
- Direct upload to your LANCommander server

## Deeper Analysis

### Architecture

The system has three main components:

1. **Server** — ASP.NET Blazor web application. Handles user authentication, game archive storage, metadata, and administration. Players connect via the desktop launcher.
2. **Launcher** — Cross-platform .NET desktop client. Auto-discovers servers on the network via UDP broadcast, browses the depot, downloads games, and manages cloud saves.
3. **Packager** — Windows-only tool for creating distributable game archives from installer executables.

### Game Distribution

- **Multi-part archive uploads** with chunked transfer for large games
- **Chunked download** on the client side with resume support
- **Automatic metadata lookup** — IGDB for game data, SteamGridDB for covers and icons
- **Redistributable management** — auto-install Visual C++, .NET, DirectX runtimes as part of game setup
- **IPX relay** (UDP port 213) for legacy game networking

### Launcher Features

- **Depot storefront** — browse by genre, popularity, and new releases
- **Library shelf** — your installed and available games
- **Download queue** with progress tracking
- **Cloud saves** — automatic backup and restore of game save files
- **UDP server discovery** — finds LANCommander servers on the network without manual IP entry
- **Media viewer** — screenshots and trailers for each game
- **Discord Rich Presence** — shows what game you're playing
- **Offline mode** — launch games without the server if already downloaded

### Server Administration

- **Web-based dashboard** — manage games, users, and settings
- **User management** — registration, approval workflows, role-based access
- **OpenID Connect** authentication support
- **PowerShell scripting** — pre/post install and pre/post launch hooks with a built-in script editor
- **RCON support** for dedicated server management
- **Play session tracking** and statistics

### Developer SDK

A .NET SDK is published on NuGet — `LANCommander.SDK` — enabling custom clients and tools that interact with the LANCommander API via dependency injection.

**Key consideration:** The Docker setup uses host network mode for UDP broadcast discovery. If your server is on a VLAN or separated network segment, ensure UDP port 35891 is reachable between subnets for server auto-discovery.

## FAQ

**Q: Can I use this for remote play or internet-based distribution?**
**A:** LANCommander is designed for local network use. It does not have built-in internet relay or TURN support. For remote scenarios, you would need to expose the server ports externally via VPN or port forwarding.

**Q: What game installers does the Packager support?**
**A:** The Packager (Windows) monitors installer executables and captures all file writes and registry changes. It should work with most mainstream installers (MSI, Inno Setup, NSIS, etc.).

**Q: Does it replace Steam, GOG, or Epic?**
**A:** No. LANCommander distributes games you already own or have the rights to distribute. It does not acquire games automatically — you package and upload them yourself.

**Q: Can multiple servers share the same game library?**
**A:** Each LANCommander server manages its own game library independently. You can run multiple servers on the same network if you want to segment content.

**Q: How does game download work on the client?**
**A:** The launcher downloads game archives in chunks with resume support. If a download is interrupted, it continues from where it left off.
