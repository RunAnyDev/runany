## Why the layout matters

The `skills/` directory with a `SKILL.md` inside a named subdirectory is the convention that has become standard for agent skills. A skill is not a library you link against. It is a markdown document with front matter that a coding agent pulls into context when the task matches.

That layout is why the repository is 38 kilobytes and still has eleven thousand stars. You do not install it. You point your agent at it, or copy the file into wherever your agent looks for skills.

The file is a landing page design guide, so the scope is narrow and the name says so. A general purpose AI design skills collection would have a directory per discipline. This one has exactly one.

## How to try it

```bash
git clone https://github.com/elayadesign/ai-design-skills.git
cd ai-design-skills
ls skills/landing-page-design
```

Then read the file. There is nothing to build, and if you are the kind of person who expects an install step, that expectation is the wrong one for this repository.

## When to use it

If you build marketing pages with a coding agent and you keep getting the same mediocre output, a design guide in the context window is a cheap intervention. It tells the agent what good looks like before it writes, which is a different lever than telling it to fix the page afterward.

It is also a clean reference for how to structure a skill yourself. One directory, one file, no packaging. The smallest possible unit of reusable agent context.

## When not to use it

A single landing page guide will not cover an app, a design system, or a native mobile interface. If your work is inside a product rather than on a marketing page, this is the wrong document.

Also weigh the licensing angle. MIT is the most permissive license you will find, so reuse is unrestricted, but you are taking a single person's design opinions as your specification. Read it before you build a process around it.
