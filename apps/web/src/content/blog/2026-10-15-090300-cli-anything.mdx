> **TL;DR:** CLI-Anything is an Apache-2.0 Python project from HKUDS whose goal is to give software command line interfaces so AI agents can drive it. It reached 52,550 stars and 4,774 forks in about seven months, with 163 open issues.

## What it is

The repository description is one line and it carries the whole thesis: "Making ALL Software Agent-Native". The argument underneath it is straightforward. Most software is operated through a graphical interface, an interface an agent cannot see or drive reliably, so the software is effectively unavailable to it. A command line interface is the part of a program an agent can use.

That framing is why this project exists rather than another agent framework. It is not trying to make the agent smarter. It is trying to widen the set of programs the agent has any way to reach.

The distribution point is a CLI hub at [clianything.cc](https://clianything.cc/), which the description links directly.

## The growth rate is the headline

Created 2026-03-08 and sitting at 52,550 stars by October 2026 is roughly 250 stars a day sustained across seven months. Put next to scientific-agent-skills, which took about a year to reach a similar count, the difference is how directly the pitch maps onto a problem people are actively trying to solve right now.

Apache-2.0 rather than MIT is a reasonable choice here. It is the more protective of the two, and for a project that expects companies to build tooling on top, the patent grant in Apache-2.0 is the part that matters.

## How to try it

```bash
git clone https://github.com/HKUDS/CLI-Anything.git
cd CLI-Anything
```

There is deliberately no install command here, because the repository description does not state one and guessing at it would be worse than leaving it out. The hub at clianything.cc is where the current distribution path lives, so start there and work back to the source.

## When to use it

It is aimed squarely at the case where you have real software with no automation surface and you want an agent in the loop. A desktop application with a GUI, an internal tool nobody has ever scripted, a platform whose API is documentation rather than code. Anything you currently operate by clicking through.

It is also useful as a design reference even if you never install it. The premise that an agent needs a CLI before it needs anything else is a good constraint to think inside.

## When not to use it

If the software you care about already has a good CLI or a real API, this solves a problem you do not have. Most developer tooling has had scriptable interfaces for years.

Second, and more importantly, this is a young project on a fast trajectory. The interfaces it generates are only as good as the reverse engineering behind them, and the last push was three weeks ago. If you are wiring something into production, pin what you depend on and re-check it.
